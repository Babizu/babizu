# 搜尋：命中方式、排序與分組

`babizu/search` 的搜尋引擎（`src/search/`）把一個查詢變成詞條、例句與釋義三區的結果。
詞與詞的比對建立在 BCDP 套件上：加權編輯距離與詞圖搜尋見 [packages/bcdp/docs/distance.md](../packages/bcdp/docs/distance.md)，
構詞搜尋見 [packages/bcdp/docs/bcdp.md](../packages/bcdp/docs/bcdp.md)。這份文件說明引擎在那之上做的事：
一個查詢詞怎麼找到詞庫中的詞、命中的詞怎麼落到記錄上、怎麼排序與分組。

| 模組 | 內容 |
|---|---|
| `engine.ts` | 門面：`SearchEngine`（搜尋、清單、相近詞、句型搜尋） |
| `term-matcher.ts` | 一個查詢詞在詞庫中的所有命中（`engine.terms`） |
| `substring-index.ts` | 前綴、結尾、包含比對的反向索引 |
| `derived-terms.ts` | 自動派生與自動同根（[derivations.md](derivations.md)） |
| `native-search.ts`、`entry-search.ts`、`occurrence-search.ts` | 族語搜尋：詞條與例句 |
| `dictionary-relations.ts` | 辭典標註的構詞關係（`engine.relations`） |
| `gloss-search.ts` | 中文、英文、臺語羅馬字釋義 |
| `scoring.ts` | 分數與排序（詞條與例句共用） |
| `family.ts` | 詞條家族與同形詞組 |

## 1. 一個查詢詞的命中

加權編輯距離只適合「長度相近、拼寫相近」的兩個詞。實際使用時有兩種需求它天生做不到：

| 使用者輸入 | 期待 | 加權編輯距離的結果 |
|---|---|---|
| `pihi`（只記得詞的開頭） | 找到 `pihilut`「尿」 | 要插入 `lut` 三個字元 ≈ 2.4，遠超過門檻 |
| `k`（想看看哪些詞、句子含有 k） | 列出所有含 k 的詞與句子 | 單一字母與任何詞的距離都很大；正規化門檻也會把長詞全部排除 |

把門檻調高並不能解決：距離門檻一旦放大到 2.4，`bintul` 也會配到幾百個無關的詞，
而且短查詢在「除以較長字串長度」的正規化下永遠吃虧。這是度量本身的性質，不是參數問題。

所以保持加權編輯距離**不變**（它負責跨方言、跨拼寫的相似比對），另外加一個**字元 → 詞**的反向索引，
負責前綴與包含比對。兩者的結果合併後再排序。

```
查詢 → ┬─ 詞圖 + 加權編輯距離 ──→ 模糊命中（含距離與規則說明）、構詞命中
       └─ 字元反向索引 ─────────→ 前綴、結尾、包含命中
                                    ↓
                        合併、去重，依等效距離（rankScore）排序
```

`TermMatcher.match()`：

1. `TermMatcher.fuzzy()`：詞圖搜尋（門檻見 `fuzziness.ts`）。有構詞規格時，構詞搜尋的通道與它共用一次詞圖走訪，
   `TermMatcher.lemma()` 收尾成自動拆解的命中。
2. `SubstringIndex.matches()`：查詢的每個字元與每對相鄰字元都有「→ 詞」的 posting，取**最短**的一個當候選集，
   再逐一驗證，分成「以查詢開頭（prefix）」「以查詢結尾（suffix）」與「包含查詢（substring）」。
   依詞長排序（越短代表多出來的部分越少），合計最多取 300 個詞。
3. 有構詞規格時，自動派生與自動同根（`DerivedTerms.find`，[derivations.md](derivations.md)）。
4. 以詞為鍵合併；同一個詞有好幾種命中方式時的取捨見第 4 節。

之後的流程完全共用：詞的 posting 指出它是哪些記錄的詞形、變體、詞根，或出現在哪些句子中，
所以每一種命中都會分別出現在「詞條」與「例句」兩區。

精確模式（門檻 0）不做構詞搜尋；中文查詢對族語欄位只做前綴與包含比對（加權編輯距離對中文沒有意義）。

### 構詞命中

語言設定檔有 `morphology` 時多三種命中，都是演算法推定的：

- **自動拆解**（`lemma`）：查衍生詞，去掉詞綴找到詞根。例如 `minudox` → `daux-`：`minu-` ＋ `dox`，其中 dox → daux 是 o→au 的方言音變。
- **自動派生**（`derived`）：查詞根，找到演算法推定由它衍生的詞，包括中綴、重疊形式，以及派生詞的派生詞。
- **自動同根**（`sibling`）：查詢與詞庫的詞推定來自同一個詞根，詞根可以不在詞庫中。

介面標「自動拆解」「自動派生」「自動同根」；辭典標註的構詞關係另外標「確定拆解」「確定派生」「確定同根」（第 3 節）。

## 2. 分數：詞條與例句同一套規則（`scoring.ts`）

分數是「等效距離」，越小越前面，分兩層算：

1. **詞的分數**（`termScore`）：查詢以什麼方式命中詞庫中的一個詞（`rankScore`）。

   | 命中方式 | 等效距離 | 介面標籤 |
   |---|---|---|
   | 模糊（fuzzy） | 加權編輯距離本身（完全相同 0、跨方言變體 0.1–0.3） | 距離不是 0 時「≈ 距離 規則」 |
   | 開頭相符（prefix） | 0.35 ＋ 多出來的字元數 × 0.05（`PREFIX_BASE_SCORE`） | 開頭相符 |
   | 結尾相符（suffix） | 與包含相同，只是分開標示、分開篩選 | 結尾相符 |
   | 自動拆解、自動派生 | 0.4 ＋ 構詞成本（`MORPHOLOGY_BASE_SCORE`） | 自動拆解／自動派生：詞綴結構 |
   | 自動同根 | 0.4 ＋ 查詢的拆解成本 ＋ 往下的成本；詞根不在詞庫中時另加詞庫外詞根的代價 | 自動同根：共同的詞根 |
   | 包含（substring） | 0.90 ＋ 多出來的字元數 × 0.05（`SUBSTRING_BASE_SCORE`） | 包含 |

   多出來的字元最多算 12 個（`EXTRA_CHAR_CAP`）。

2. **記錄的分數**（`recordScore`）：那個詞和這一筆記錄的關係。
   - 詞就是記錄的詞形、變體、其他寫法，或出現在句中：不加。
   - 經由**辭典標註**的構詞關係（第 3 節）：每一層加 0.1（`DERIVATIVE_PENALTY`），同根是往上加往下的層數，排在詞本身之後。

這組數字讓各種命中互相穿插得合理：

- `bintul`：精確命中（0）與跨方言的 `bintun`（0.1）仍在最前面，開頭相符的 `bintulan`（0.45）其次。
- `pihi`：開頭相符的 `pihilut`（0.50）排在「拼寫接近但距離較大」的 `pihik-`（0.80）之前——
  使用者打前四個字母時，想找的通常是那個以它開頭的詞。
- `usa`：辭典列在 usa 條下的 mukusa（0.1）排在自動派生的 dusa（0.8；tu- 加兩條音變，是雜訊）與只是包含 usa 的詞（0.95 起）之前。

每一筆結果都標示命中方式，使用者知道自己為什麼會看到這一筆。辭典標註的關係與演算法推定的關係用不同的標籤（「確定…」對「自動…」，見 [concepts.md](concepts.md)「辭典標註與自動推定」）。

**排序**：詞條（`compareHits`）依自動同根在後、分數、命中方式、詞長、命中身分、角色、記錄長度；
例句（`compareOccurrences`）依自動同根在後（句中有任何一個查詢詞是自動同根）、分數（各查詢詞相加）、最弱的命中方式、距離、句長。

**自動同根排在原本的命中之後，不佔上限**（`siblingTier`）：同根詞的詞條與例句都列出，但一律排在其他命中之後；
每個區塊的上限（`limit`，預設 500）只算原本的命中，同根詞另外全列。詞庫中常用詞根的同根詞可以出現在幾百句例句中，
不這樣做時它們會把分數較差的原本命中擠出上限。詞條家族同樣：只有自動同根的家族排在後面。
多詞查詢的例句只要有一個查詢詞是自動同根就算這一層：這句是靠自動同根才成立的。不能只看句子的命中方式
（最弱的一種）：結尾相符、包含比自動同根弱，「一個詞自動同根、另一個詞結尾相符」的句子會佔上限。

## 3. 辭典的構詞關係（`DictionaryRelations`）

以查詢為詞形的記錄（「自己」，寫法與查詢相同、模糊距離 0）在詞條家族（`docs.parent`，第 6 節）中的：

| 關係 | kind | 標籤 | 層數 |
|---|---|---|---|
| 上層：自己所屬的條目、自己標明 `<` 的詞 | `parent` | 確定拆解 查詢 | 往上幾層 |
| 下層：條目下的詞形、標明 `<` 查詢的另立條目，以及詞根 posting 指到、接不上家族的記錄 | `root` | 確定派生 查詢 | 往下幾層 |
| 同一個上層的其他詞（扣掉自己這一支） | `sibling` | 確定同根 上層 | 往上＋往下 |

- 只收詞與詞綴，不收片語與例句；每筆記錄取最淺的一種。
- **詞綴的條目不算同根的依據**：辭典把帶某個詞綴的詞列在詞綴的條目下當例子（《巴宰語詞典》<in> 條下的 kinawas、binaket），
  它們共有的是詞綴，不是詞根。上層是詞綴的條目時只算確定拆解（kinawas 拆出 <in>），不把它底下的其他詞算成同根。
  詞綴由語言設定檔的構詞規格判斷（上層的詞形是規格中的前綴、後綴、中綴或環綴的一側）；
  詞根的條目（kita-、kawas-）也常寫成帶連字號，只看寫法分不出來。
- 詞條直接列出這些記錄（`DictionaryRelations.of`）；例句則是句中出現這些記錄的寫法時（`DictionaryRelations.tokens`，第 5 節）。
- **只從寫法與查詢相同的詞條展開**：寫法相近的詞條已經是一層不確定（第 5 節的 sungut、zenget）。
- 例：查 pinakita（kita- 條 pakita 底下）：pakita、kita- 是確定拆解（0.1、0.2），kita- 條下的其他詞（kinita、mikita…）是確定同根。
- 家族中以辭典關係命中的列不另加標籤（樹狀排列已經看得出關係），家族的排序也不把它們算成獨立的證據（`DICTIONARY_KINDS`）。
  但記錄原本也被直接命中時（例如自動拆解到的詞根 kawas-，因為辭典也標明而改以確定拆解呈現）仍算（`EntryHit.direct`）：
  否則查 kinawas 時，kawas- 條會因為證據變少而排到 <in> 條之後。

## 4. 同一個詞有多種命中方式（`mergeMorphMatch`）

同一個詞庫詞可能同時是模糊命中、開頭相符、包含與構詞命中，每個詞只保留一種：

- 模糊與開頭相符、包含之間：以模糊命中為準（有距離資訊可以顯示規則）。
- **開頭相符、包含的詞能被 BCDP 分析時**（自動派生圖在模糊程度的上限內走得到它，或自動拆解得到它）：
  一律改以構詞命中呈現，附上派生或拆解的說明；分數取兩者較好的。
  開頭相符只看字串，BCDP 分析得出來時說明比「開頭相符」有用，名次也不該因此變差。
  例：查 kita，kitakita'en 開頭相符（0.70）又是自動派生（kita'en 的重疊），標為自動派生、分數 0.70。
- 構詞命中與模糊命中之間：**取等效距離較好的一種**，同分時模糊命中優先（直接相符）。
  只看命中方式是不夠的：模糊門檻隨查詢長度變大（「標準」7 個字元是 1.25），刪掉一個短前綴（p 1.0）加上一兩條方言規則就落在門檻內。
  查 `parazem` 時，`razem` 的模糊距離是 1.2，而構詞分析 pa- ＋ razem 只要 0.2；一律保留模糊命中的話，
  越透明的拆解（短詞綴、長查詢）越容易被較差的模糊命中蓋掉。
- **自動同根不取代其他命中**：它要先往上到查詢的詞根再往下，是把握最小的一種；只補上原本沒有的詞，
  開頭相符、包含也不例外。同一筆記錄有好幾個命中時也一樣（`replacesRecordHit`）。
  加上排在最後、不佔上限，原本的結果一筆都不變。

被取代的命中留在 `others`（`alternativesOf`）：使用者排除取代它的搜尋方法時，改用原本的（第 7 節）。

## 5. 例句：每個查詢詞在句中的命中（`searchOccurrences`）

例句與詞條用同一份命中清單（`TermMatcher.match`）、同一套分數，差別只在「詞和記錄的關係」：

1. **句中的詞就是命中的詞庫詞**：詞的分數。句中的詞是 token posting，所以開頭相符、包含、自動拆解、自動派生都照樣適用。
2. **句中的詞與查詢有辭典的構詞關係**（`DictionaryRelations.tokens`，第 3 節的關係換成寫法）：
   - 句中出現查詢的上層、下層、同根詞的寫法時，分數是查詢的分數加上層數 × 0.1，標籤是「確定拆解／派生／同根」。
   - 例：查 usa，mukusa（《巴宰語詞典》p.204 另立條目「< usa」、usa 條下的詞形）所在的例句分數 0.1，
     排在含 usa 本身的例句之後、自動派生的 dusa 之前。
   - **只從寫法與查詢相同的詞條展開**（模糊距離 0）。寫法相近的詞條已經是一層不確定，
     再加上派生就不是查詢的那個詞了：sungut 與 zenget 只差三條方言規則（s→z、u→e、u→e，0.3），卻是不同的詞；
     若也展開，zenget 條下的 kizenget 會以 0.4 排在 sungut 真正的派生詞 pausunguday（0.65）之前。
     相近寫法的派生詞仍可經由自動派生找到，分數照實加上寫法的差距。
3. 同一句同一個查詢詞有好幾種命中時取分數最好的一種，說明標籤（`OccurrenceHit.matches`）也是那一種；
   多詞查詢時各詞的分數相加，每個詞一組標籤。重複的查詢詞只比對一次。
4. 對齊與構詞說明只為前 `explainLimit`（40）句計算；同一對（查詢詞, 詞）在一次搜尋中只算一次，
   含同一個詞的各句共用同一個命中物件。
5. 已經是詞條命中的記錄不再列為例句。

## 6. 詞條家族與同形詞組（`family.ts`）

### 詞條家族

辭典常把衍生詞列在詞根條目底下（《巴宰語詞典》kita- 條下有 pakita，pakita 底下又有 pinakita），
也常把衍生詞另立條目並標明來源（p.225 的 pakita：「< kita-」）。如果各自依分數排序，
這些資料已經確認相關的結果會散在清單各處。所以詞條區以**詞條家族**為單位：

1. **上層記錄**（建索引時計算，`docs.json` 的 `parent`）只取資料明確寫出的關係：
   - 詞條群組（`group.type` 為 `entry`）中的詞形、例句：`group.parent`，沒有指定時是群組的詞目；
   - `related` 中的 `derived-from` 連結；
   - 另立條目的詞目，`morphology.derivedFrom` 的 `<`：同一來源中寫法相同的詞目。
     依序試原文與去掉註記的寫法（「kawas?」、「bair- = bail-」）；**對不到唯一一個詞目就不連**：
     同形異義詞（apu 有兩個條目）寧可分開，也不要接錯。
   - 最後切斷循環，每筆記錄都走得到樹根。
2. **分組**：命中依樹根分組；命中記錄到樹根之間的上層即使沒有命中也列出來（看得出位置）。
   另立條目的詞目若與同一層某個詞形寫法相同（kita- 條下的 pakita 與 p.225 的 pakita），併成一列，
   同一個詞在家族中只出現一次，位置就是辭典列出它的地方。
3. **家族的名次**取家族中最好的命中：子項目與查詢完全相同，整個家族就排到最前面，詞根仍在區塊頂端。
   同分時依序比較：達到最好分數的命中數、命中總數（以詞根身分命中的都不算，那是詞根命中的連帶結果）、
   最好的命中本身（與原本的詞條排序相同）。查 `kinawas`：kawas- 條（自動拆解＋ kinawas）排在
   只以 kinawas 為例的 <in> 條之前。
4. **家族內**同一層依子樹中最好的分數排，同分依辭典中的順序。

分組只是重新排列：`entries` 仍是依分數排序的命中清單，`entryGroups` 是同一批命中依家族排列的結果，
每個命中恰好出現一次。其他來源的同一個詞（分類詞表、詞彙表）不屬於辭典的詞條結構，交給下一步的同形詞組。

### 同形詞組：寫法完全相同的單獨結果合成一項

不同來源常各有一筆同一個詞（mikita 在噶哈巫分類辭典、潘德興詞彙表各一筆），分開列只是讓讀者一筆一筆比對。
所以分組之後再做一步（`mergeSpellings`，查詢時計算，不動索引）：

1. **只合併單獨的結果**（只有一筆、沒有子項目的組）。寫法的比較是 `spellingOf`：NFC 正規化、去掉頭尾空白，
   **其餘逐字相同**——附加符號不同就是不同的寫法（maturai 與 mātūra͡i 分開），因為那是原書的轉寫差異，讀者要看得到。
2. **家族維持原樣**：kita- 條與它底下的派生詞本身就是一個階層，不拆開、也不塞進詞組。
   家族中寫法相同的那一列另外**複製一份**進詞組（`family` 指向家族的樹根），介面標「也列在 kita- 條下」，
   讓跨來源比較時看得到辭典的那一筆；家族中原本的位置不變。
   複製的那一筆若與某個單獨結果同一來源、釋義也相同（apui 的另立條目與 apu 條下的 apui），就不複製，避免同一筆出現兩次。
3. **名次**：詞組排在其中第一個單獨結果原本的位置；總數與截斷都以合併後的項目計算。
4. 至少兩筆才成組；只有一筆時仍是一般的結果列。

## 7. 搜尋方法：個別顯示或排除（`exclude`、`methods`）

每個命中屬於一種搜尋方法（`scoring.ts` 的 `methodOf`；經過好幾種關係時取把握最小的：自動 ＞ 部分符合 ＞ 確定 ＞ 拼寫）：

| 組 | 方法 |
|---|---|
| 拼寫 | `exact` 完全相符、`fuzzy` 相近拼寫 |
| 部分符合 | `prefix` 開頭、`suffix` 結尾、`substring` 包含 |
| 確定（辭典標註） | `dictLemma` 拆解、`dictDerived` 派生、`dictSibling` 同根 |
| 自動（演算法推定） | `lemma` 拆解、`derived` 派生、`sibling` 同根 |

- `search(q, { exclude })`：排除的方法**在挑每筆記錄最好的命中之前**就拿掉，不會壓在其他方法底下。
  同一個詞被另一種命中取代時，被取代的留在 `others`：查 sungut 時 sungutan 是自動派生（取代了開頭相符）；
  排除自動派生後，它改以開頭相符出現，不會跟著消失。
- `response.methods`：每種方法找得到幾筆記錄（詞條與例句），**不受排除影響**，介面在每個選項旁顯示（`method-tally.ts`）。
- `response.methodGroups`：每一組找得到幾筆記錄，是組內各方法的聯集，同樣不受排除影響；介面在收合的組名旁顯示。
- 網址參數 `x=`（逗號分隔的排除清單）；預設全部顯示。

## 8. 釋義搜尋（`gloss-search.ts`）

- **中文**：「單字 → 記錄」反向索引，取查詢中各漢字 posting 的交集，再驗證整個查詢是子字串。
- **英文、臺語羅馬字**：「詞 → 記錄」反向索引，另保留排序後的詞表；每個查詢詞都要命中（整詞，或至少 3 個字母時的詞首）。
  英文虛詞（a、the、of…）不算；全部都是虛詞時不搜尋釋義。
- 依「某義項完全相同、某義項以查詢開頭、整詞包含、其他」分級，再依角色與長度排序。

兩個索引都在第一次用到時才建立；`engine.warmup()` 可以預先建立。

## 9. 成本

- 記憶體：字元 → 詞的反向索引，1.2 萬個詞約 8 萬筆 posting，載入後建立約 10 ms。
- 查詢：候選集是最短的字元或字元對 posting。最壞情況是查單一常見字母（例如 `a`），驗證一次約 1–2 ms。
- 結果量：單字母查詢會命中數百個詞、上千個句子，因此有 300 個詞的上限，介面也分頁顯示，並在總數上標明截斷。

**為什麼不用其他方案**：

| 方案 | 不採用的原因 |
|---|---|
| 把 maxDistance 調大 | 短查詢會配到大量無關長詞，精確查詢的品質一起崩掉 |
| 在詞圖上做前綴走訪 | 只能解決前綴，解決不了「包含」；而且詞圖已被模糊搜尋使用，混在一起會讓剪枝邏輯難以維護 |
| n-gram 索引（2-gram、3-gram） | 空間大得多，且單一字母查詢仍需另外處理；字元索引 + 驗證已經夠快 |
| 後綴陣列／後綴自動機 | 能做到 O(查詢長度) 的包含比對，但建置與序列化複雜度高出許多，對 1.2 萬個詞的規模不划算 |

## 10. API 摘要

```ts
import { buildSearchIndex, levelOf, SearchEngine } from 'babizu/search'

const { docs, lexicon } = buildSearchIndex({ items, groups, sourceIds, profile, varieties }) // 建置端
const engine = new SearchEngine({ docs, lexicon, profile, derivations }) // 瀏覽器（Web Worker）
engine.search('bintul', { fuzziness: 'normal', filters: { dialects: ['pazeh'] }, exclude: ['substring'] })
engine.searchPattern('yaku ka _* isiw') // 句型搜尋（pattern-query.md）

// 一個查詢詞在詞庫中的所有命中（評估工具、句型搜尋）
engine.terms.match('bintul', levelOf('normal'), { visitedNodes: 0 })
engine.terms.lemmaHits('minudox', levelOf('normal')) // 只做自動拆解
```

| 類別／函式 | 說明 |
|---|---|
| `SearchEngine` | `search`、`list`、`neighbors`、`docById`、`searchPattern`、`explainMorphology`（演算法實驗室）、`warmup`；`terms`（`TermMatcher`）、`relations`（`DictionaryRelations`）、`createFilter` |
| `FUZZINESS`、`levelOf`、`lemmaMax`、`fuzzyOptions` | 模糊程度：距離門檻、構詞搜尋的總成本上限、詞圖搜尋的選項 |
| `buildEntryGroups`、`mergeSpellings`、`spellingOf` | 詞條家族與同形詞組 |
| `buildDerivationGraph`、`DerivationGraph` | 自動派生圖（[derivations.md](derivations.md)） |
| `buildParseChart`、`ParseChart` | 拆解表（句型搜尋的構詞樣式用，[pattern-query.md](pattern-query.md)） |
| `Checklist` | 檢查清單：例句中沒有辭典條目的詞、詞形完全相同的詞條、重複的例句、人工拆解與構詞樣式的對照 |
