# 多語言介面

介面字串直接用中文寫在程式裡：在 Vue 元件與原始碼中看到的就是畫面上的中文，搜尋程式碼時用中文就找得到。
其他語系是「中文原文 → 譯文」的對照表（gettext 的做法）。站台自己的內容（名稱、方言名稱、「關於」頁…）則在站台設定裡依語系提供。

## 內建語系

| 代碼 | 名稱 | 字串從哪裡來 |
|---|---|---|
| `zh-TW` | 中文 | 程式裡的原文，沒有語系檔 |
| `en` | English | `locales/en.json`：中文原文 → 英文 |

單元測試（`test/site/locales.test.js`）從程式碼抽出所有介面字串，檢查 `en.json`：每個字串都有譯文、沒有程式已經不用的鍵、參數佔位符 `{name}` 與中文一致。

## 在前端程式中使用

```vue
<script setup>
import { useI18n } from '@/i18n.js'
const { t, tr, formatCount } = useI18n()
</script>

<template>
  <p>{{ t('找不到「{query}」的結果', { query }) }}</p>  <!-- 介面字串，{query} 代入參數 -->
  <p>{{ t('詞條', null, '角色') }}</p>                   <!-- 同一句中文要有不同譯文時加語境 -->
  <h1>{{ tr(site.title) }}</h1>                         <!-- 站台設定中依語系提供的文字 -->
  <span>{{ formatCount(12345) }}</span>                 <!-- 依語系加千分位 -->
</template>
```

- `t(原文, 參數, 語境)`：依序查目前語系、預設語系的譯文，都沒有就顯示中文原文。
- **語境**：同一句中文在不同地方要翻成不同譯文時才需要。例如「詞條」當頁面標題是 Entry、當例句的角色是 Headword：
  `t('詞條', null, '角色')`，譯文檔的鍵寫成 `"角色|詞條"`。
- **不在 t() 呼叫處直接寫出來的字串**（代碼 → 名稱的對照表、路由的頁面標題、選單項目）用 `msg('…')` 包起來。
  `msg` 原樣傳回鍵，作用是讓抽取工具找得到這些字串：

  ```js
  import { msg, t } from '@/i18n.js'
  const STATUS_LABELS = { unreviewed: msg('未校對'), reviewed: msg('初步校對') }
  t(STATUS_LABELS[code])
  ```

- 抽取工具只認得單引號的字面字串。不要用變數或樣板字串組出字串（`` t(`unit.${code}`) ``）：
  掃不到，也沒辦法從程式直接看出畫面上的文字。代碼的顯示名稱用 `app/src/lib/labels.js` 的表與輔助函式。
- 新增或修改介面字串時，同時在 `locales/en.json` 加上（或改掉舊的鍵）；忘了的話單元測試會列出來。

不使用 vue-i18n：需要的只是「查字串＋代入參數＋回退」，自己寫不到一百行，也少一個依賴。

## 站台啟用哪些語系

```js
// babizu.config.js
export default defineSite({
  locales: ['zh-TW', 'en', 'pzh'], // 第一個是預設語系（或另外指定 defaultLocale）
  localeNames: { pzh: '族語' }, // 語系選單上的名稱；內建語系已有名稱
  // …
})
```

- 只有一個語系時不顯示語系選單。
- 第一次來訪時依瀏覽器偏好語言選擇（完全相符優先，其次主要語言相同，例如 `en-US` → `en`），都不符合就用預設語系。
- 讀者的選擇存在瀏覽器（`<站台 id>:locale`），並設定 `<html lang>`。
- 預設語系不是中文時，它必須有譯文（框架內建或站台提供）。

## 覆寫字串、新增語系

在站台目錄的 `locales/<語系>.json` 放要覆寫或新增的譯文，格式與 `en.json` 相同：扁平的「中文原文 → 譯文」。
只需要寫想改的字串；中文也可以覆寫（`locales/zh-TW.json`）：

```json
{
  "「標準」會找出方言間的語音對應與少量拼寫差異；…": "「標準」會找出方言對應（例如 r 脫落、詞尾 l→n）與少量拼寫差異；…"
}
```

鍵是框架程式裡的中文原文。框架改了原文之後，舊的覆寫就不再生效；`babizu check` 與 `babizu locales` 會列出這些失效的鍵。

**新增語系**（例如族語介面）時，可以先只翻一部分：缺少的字串會回退到預設語系、再回退到中文。
`babizu locales` 列出每個語系缺少的字串，輸出可以直接貼進語系檔再填譯文：

```
$ npx babizu locales
pzh（族語）缺 364 個譯文：
  "{count} 段錄音": "",
  …
```

## 依語系提供的站台內容

站台設定中標為 Localized 的欄位（`title`、`description`、`varieties[].label`、`examples[].note`、`footer`、`about`…）
可以是字串或 `{ 語系: 文字 }`，缺的語系用預設語系的內容。見 [site-config.md](site-config.md)。

語言設定檔中規則分類的名稱也可以依語系提供（`rules[].label`），演算法實驗室與搜尋結果的說明會使用。
