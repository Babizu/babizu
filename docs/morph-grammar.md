# 構詞文法：詞素、組合規則與包覆單位

> 搜尋演算法見 [bcdp.md](bcdp.md)，語言設定檔的寫法見 [language-profile.md](language-profile.md#構詞文法)。
> 這份文件說明四件事：
>
> - 構詞文法怎麼寫；
> - 它怎麼在載入時展開成平面清單（編譯原理與引理）；
> - BCDP 為此做的唯一推廣：包覆單位；
> - 這一版拿掉了什麼、為什麼。

## 0. 摘要

**文法是巨集**。語言設定檔可以用兩種寫法描述構詞，搜尋演算法只認得其中一種：

- **平面清單**：前綴、後綴、中綴、重疊、環綴各一張表，是搜尋演算法看得懂的寫法。
- **文法**：寫出最小詞素（同一個詞素的幾個形式寫在一起），以及它們依什麼順序組合成固定的構式（組合規則）。

文法在載入時**展開**成平面清單，每一項帶著它由哪些詞素構成（`parts`），說明時顯示詞素。展開之後就是一份普通的平面規格，BCDP 不知道文法的存在。

平面清單比原版多一種形狀，就是**包覆單位**：

- 它是緊貼詞根的前綴字串 L、詞根上的中綴或重疊 op、緊貼詞根的後綴字串 R，合起來算一個步驟。
- 原版的單獨中綴、單獨重疊、三種環綴，都是它的特例。
- 新增的只有「前綴 ＋ 詞根上的中綴」（m<a>-），以及它再加後綴（m<a>-…-ay）。

**沒有**的東西：

- 同位詞素條件；
- 懲罰；
- 第二個搜尋演算法或仲裁者。

同分時說明選哪一個分析，由一個固定的順序決定。這個順序只影響標註，不影響成本。

| | 原版 BCDP ＋ 平面清單 | 這一版 ＋ 文法 |
|---|---|---|
| mausay 的分析 | ma-…-ay（標註錯） | m<a>-…-ay，主事焦點・非實現 |
| minubaket／mubinaket | 都是 minu-／mu- ＋ <in>，但組合寫死在清單裡 | m<in>u-（AF.PFV）／mu- ＋ b<in>aket，依推導順序區分 |
| 同一份平面清單上的結果 | — | 每個詞根的成本逐位元相同 |
| 耗時（同一份清單，只換演算法） | 1 | 1.00× |
| 耗時（各用自己的規格） | 1 | BCDP 本身 1.00–1.02×，含構詞的搜尋 1.02–1.03×，在量測誤差之內（第 7 節） |
| 找詞根第 1 名（S1） | 81.1% | 81.4% |

## 1. 問題

### 1.1 平面清單的例子

`pazeh-kaxabu.json` 原本的前綴清單中有這些項目：

| 清單中的形式 | 實際的構成 | 說明 |
|---|---|---|
| minu、mini、mine | m<in>u、m<in>i、m<in>e | 中綴 <in> 插在主事焦點前綴裡 |
| kina、pina | k<in>a、p<in>a | 中綴 <in> 插在 ka-、pa- 裡 |
| ma（M-…-ay 的一種） | m<a>，接元音開頭的詞根 | 中綴 <a> 插在 m- 之後 |

m-、mu-、mi-、me- 則各自是獨立的前綴，看不出它們是同一個詞素（Lim & Zeitoun 2024 §51.2.4）。

### 1.2 後果

- **標註錯誤**：`mausay`（要去）被分析成 ma- ＋ usa ＋ -ay。詞根 usa 是對的，標註卻錯了。潘德興詞彙表的分析是 `m<a>us(a)-ay`（主事-非完成貌-去=非現實）。
- **維護負擔**：每新增一個前綴，就要手動想出它與每個中綴的組合。
- **推導順序看不出來**：minubaket（m<in>u- ＋ baket，先加 mu- 再插 <in>）與 mubinaket（mu- ＋ b<in>aket，先插 <in> 再加 mu-）表面不同、意義不同，平面清單中卻只是兩個不相干的字串。

## 2. 模型

### 2.1 分析

一個分析是：

> 前綴鏈 · 〔包覆單位〕 · 詞根 · 後綴鏈

- **詞綴**：一側的字串（前綴或後綴），可以串接；每側至多 `maxSteps` 個。
- **包覆單位** κ ＝ (L, op, R)：緊貼詞根，一個分析至多一個，算一個步驟，成本 c_κ。
  - L：詞根前面緊貼的前綴字串。
  - op：詞根上的運算，也就是中綴（插在詞根首輔音之後）或重疊模板，在查詢端還原（bcdp.md 1.4）。
  - R：詞根後面緊貼的後綴字串。
  - 各部分都可以沒有，但至少要有 op，或 L、R 都有。唯一的例外見 2.3 節：只有 L 的「詞根元音開頭」包覆單位。
- 底層字串是 π · L · op(t) · R · σ（π、σ 是前綴鏈、後綴鏈，t 是詞根）。
- **成本** ＝ 步驟成本 ＋ 查詢與整個底層字串的加權編輯距離，交界語意與原版相同（bcdp.md 1.2–1.3）。沒有條件、沒有懲罰。

原版已有的形狀都是包覆單位的特例：

| 形狀 | 原版的名稱 | 例子 |
|---|---|---|
| (∅, op, ∅) | 單獨的中綴、重疊 | b<in>aket、da~dius |
| (L, ∅, R) | 前綴式環綴 | ta-…-aw |
| (∅, op, R) | 中綴式、重疊式環綴 | <in>…-an、Ca~…-ay |
| **(L, op, ∅)** | 新增 | m<a>-：mbaaket |
| **(L, op, R)** | 新增 | m<a>-…-ay：maudanay |

### 2.2 為什麼 m<a> 不需要條件

語法描述說：主事焦點的非完成貌是 m ＋ <a>，「只接元音開頭的詞根」。原本以為這要寫成一個條件，其實它是中綴位置的推論。

「只有輔音的前綴 ＋ 中綴」與「前綴 ＋ 詞根上的中綴」在任何詞根上表面都相同，因為中綴插在整個詞的首輔音之後，而 m 沒有元音，首輔音一定延伸到詞根裡：

- m ＋ <a> ＋ usa ＝ m · a · usa ＝ mausa（usa 的首輔音是空的）
- m ＋ <a> ＋ baket ＝ m · b · a · aket ＝ mbaaket

所以 m<a> 編成包覆單位 (m, <a>, ∅)，中綴在詞根上還原。原版既有的一致性檢查「拿掉中綴之後，詞幹的首輔音不變」（`restored()`）自然決定了對錯：

- **mausa**：拿掉 a 之後是 usa，首輔音仍是空的 → 接受：m<a>- ＋ usa。
- **mabaket**：若把 a 當成中綴，拿掉之後是 baket，首輔音由空的變成 b → 拒絕。只剩 ma- ＋ baket（靜態）。

「m<a> 只接元音開頭的詞根」因此不是另外加的規則：m<a>- ＋ baket 的表面是 mbaaket，本來就不是 mabaket。

### 2.3 同一個組合，兩種還原方式

還原變體的交界是固定的（bcdp.md 1.4）：詞幹的兩端釘在查詢的位置上，方言規則不能跨越。這在 m<a>…-ay 上有代價：

- mausay ＝ m<a>- ＋ usa ＋ -ay：交界上的 a｜a 要由規則 aa → a（0.1）合併；
- 固定交界不允許這條規則跨越，於是 (m, <a>, ay) 這個變體在 mausay 上只能付一次刪除（1.0），分析就落到 ma- ＋ usa ＋ -ay（靜態・非實現）上。

但是在元音開頭的詞根上，(L, <x>, R) 本來就是串接：L · x · r · R。所以編譯器對「外側有前綴、中綴落在詞根上」的組合另外產生一項**串接的前綴式環綴**：

> (L·x, ∅, R)，詞根必須以元音開頭（`stemInitial: 'V'`）

- 它是一般的前綴式環綴，交界語意完整，aa → a 可以跨越 usa｜ay；mausay 因此是 m<a>-…-ay，0.2 ＋ 0.1 ＝ 0.3。
- R 是空的也可以（`{ prefix: 'ma', stemInitial: 'V' }`）：這時它是「只能緊貼元音開頭詞根的前綴」，詞尾照一般的後綴鏈處理。
- 兩項表示同一個組合規則，成本、說明、`parts`、同分順序都相同。
- 輔音開頭的詞根只有包覆單位那一項適用：m ＋ b<a>aket 由 (m, <a>, ∅) 在詞根上還原。
- 元音開頭的詞根兩項都適用，得到的是同一個分析。串接那一項允許規則跨越交界，成本不會比較高，兩者取 min。

「詞根元音開頭」不是條件，是中綴位置的定義：只有在元音開頭的詞根上，這個組合的表面才是 L·x 接在詞根前面。它由詞圖走訪的第一條邊檢查（5.2 節），是精確的篩選，不是懲罰。

### 2.4 同分時的說明

兩個分析的成本相同時，說明依下列順序選一個。成本不受影響，只影響標註：

1. 步驟少的優先。
2. 依展開後的順序（rank）：
   - 自由詞素在前（依規格順序），組合規則在後（依規格順序）；
   - 平面清單寫法：前綴、後綴、中綴、重疊、環綴，各依清單順序。

例子：mausa 可以是 ma- ＋ usa（靜態），也可以是 m<a>- ＋ usa（主事焦點・非完成貌），兩者都是 0.2、一個步驟。依第 2 項，說明選自由詞素 ma-。

為什麼自由詞素在前：同分時，一個自由詞素是比較簡單的解釋，組合規則則是語法上更特定的主張。決定這個順序時的例子：組合規則引用 AF 的全部形式時，噶哈巫語的 `modaux` 可以是 mu- ＋ daux（前綴的 u → o，0.1），也可以是 m<a>u- ＋ daux（前綴的 au → o，同樣 0.1），前者才對。這種「單一詞素 vs 組合規則」的同分，比「兩個組合規則之間」的同分常見得多。（巴宰語的設定檔之後把 AF.PROG 限縮成只用 m-，不再有 mau-，見 language-profile.md 的編寫技巧。）

實作上這個順序在每一個取 min 的地方套用（5.3 節）。它是逐點的選擇，不保證在所有同分分析中取整體最小的那一個，但結果是確定的、與輸入順序以外的東西無關。

## 3. 寫法

文法寫法與平面清單寫法二選一，不能混用。`cost`、`minStem`、`maxSteps`、`lemmaSpread`、`vowels`、`alternations` 兩種寫法共用，意思相同。

```json
"morphology": {
  "cost": 0.2,
  "morphemes": [
    { "id": "AF", "type": "prefix", "forms": ["m", "mu", "mi", "me"], "gloss": { "zh-TW": "主事焦點", "en": "AF" } },
    { "id": "STAT", "type": "prefix", "form": "ma" },
    { "id": "PROG", "type": "infix", "form": "a" },
    { "id": "PRF", "type": "infix", "form": "in" },
    { "id": "IRR", "type": "suffix", "form": "ay" },
    { "id": "HORT", "type": "prefix", "form": "ta", "free": false },
    { "id": "RED.CV", "type": "reduplication", "pattern": "CV" }
  ],
  "constructions": [
    { "id": "AF.PFV", "sequence": ["AF", "PRF"], "gloss": { "zh-TW": "主事焦點・完成", "en": "AV.PFV" } },
    { "id": "AF.IRR", "sequence": ["AF", "PROG", "IRR"], "gloss": { "zh-TW": "主事焦點・非實現", "en": "AV.IRR" } }
  ]
}
```

### 3.1 詞素（`morphemes`）

| 欄位 | 說明 |
|---|---|
| `id` | 識別碼，組合規則以它引用；不能重複 |
| `type` | `prefix`、`suffix`、`infix`、`reduplication` |
| `form` 或 `forms` | 形式（恰好寫一個）。`forms` 是同一個詞素的幾個形式（同位詞素），只是字串清單，**沒有條件**：用了哪一個由查詢本身決定 |
| `pattern` | 重疊型式（只用於重疊，取代 `form`）：`Ca`、`CV`、`CVV`、`CVN`、`CVCV`、`CVCVC`、`full` |
| `gloss` | 說明，字串或依語系的物件 |
| `cost` | 單獨出現時的步驟成本，預設取頂層的 `cost` |
| `free` | `false`：只出現在組合規則裡，不能單獨分析（例如只與 -i、-aw 一起出現的勸說 ta-） |
| `ref`、`note` | 出處與附註，只供維護者查證 |

### 3.2 組合規則（`constructions`）

| 欄位 | 說明 |
|---|---|
| `id` | 識別碼，不能與其他組合規則或詞素重複 |
| `sequence` | 至少兩個詞素 id，依**推導順序**（先加上去的在前） |
| `gloss`、`cost` | 整個構式的說明與成本（算一個步驟），成本預設取頂層的 `cost` |
| `ref`、`note` | 同上 |

推導順序決定表面：`["AF", "PRF"]` 是先加 mu- 再插 <in>（minu-），`["PRF", "AF"]` 是先插 <in> 再加 mu-（mu- ＋ b<in>aket）。後者通常不必寫成組合規則：兩個自由步驟就找得到，只是沒有構式的說明。

### 3.3 平面清單寫法的包覆單位

不寫文法時，`circumfixes` 可以直接寫包覆單位：`prefix` 與 `infix`（或 `reduplication`）同時出現，`suffix` 可有可無：

```json
{ "prefix": "m", "infix": "a", "suffix": "ay", "gloss": "AV.IRR" }
{ "prefix": "ma", "suffix": "ay", "stemInitial": "V", "gloss": "AV.IRR" }
```

- 至少要有兩個部分。唯一的例外是有 `stemInitial` 的前綴（2.3 節），它可以單獨出現。
- `infix` 與 `reduplication` 不能同時出現（一個分析只有一個詞根上的運算）。
- `stemInitial` 只能是 `"V"`（詞根以元音開頭），而且只用於前綴式（可以帶後綴）。

## 4. 編譯

### 4.1 符號推導

一條組合規則是一串詞素。把詞根當成一個內容未知的符號 X，狀態 (L, op, R) 由 (∅, ∅, ∅) 開始，依推導順序套用：

1. **前綴** p：L ← p · L。
2. **後綴** s：R ← R · s。
3. **中綴** x：
   - L 含元音：插在 L 的首輔音（群）之後。例：mu ＋ <in> → minu。
   - L 沒有元音（空的，或只有輔音）：插入點在 X 的首輔音之後，所以落在詞根上：op ← x。例：m ＋ <a> → (m, <a>, ∅)。
4. **重疊**：只能是第一個（直接加在詞根上），op ← 重疊。
5. op 已經有了，又來一個落在詞根上的中綴 → 規格錯誤；重疊不是第一個 → 規格錯誤。錯誤訊息指出是哪一條規則、哪一種同位詞素選擇、第幾個詞素。

### 4.2 輸出

| 推導的結果 | 輸出 |
|---|---|
| 沒有 op，只有 L | 一個前綴（可以串接，不必在最內層） |
| 沒有 op，只有 R | 一個後綴 |
| 只有 op | 單獨的中綴或重疊 |
| 其他 | 一個包覆單位（`circumfixes` 的一項） |
| op 是中綴而且 L 不空 | 另外先產生 (L·x, ∅, R) 且 `stemInitial: 'V'`（2.3 節） |

- 每一項帶 `parts`（詞素、形式、依推導順序）、組合規則的 `gloss` 與 `cost`、同分順序 `rank`。
- 自由詞素一個形式一項：前綴、後綴是詞綴；中綴、重疊是 (∅, op, ∅)。
- 只有一側的組合規則（minu、kina、mau…）是**一般的詞綴**，可以不在最內層：kina- ＋ tu- ＋ babaw（kinatubabaw）因此找得到，過去要靠「未收錄的組合」。

### 4.3 引理（忠實性）

> **引理**：對任何含元音的詞根 r，把序列直接套在 r 上（中綴插在當時整個詞的首輔音之後）的結果，等於 L · op(r) · R。

<details>
<summary>證明</summary>

對序列長度 k 歸納，不變量是「第 k 步之後的詞 w_k ＝ L_k · op_k(r) · R_k」（op_k 沒有時 op_k(r) ＝ r）。k ＝ 0 時 w₀ ＝ r，成立。

- 前綴 p：p · w ＝ (p · L) · op(r) · R。
- 後綴 s：同理。
- 重疊：只在第一步，L、R 都是空的，w₁ ＝ red(r)。
- 中綴 x，L 含元音：w 的首輔音落在 L 之內，等於 L 的首輔音，插入點在 L 之內。
- 中綴 x，L 沒有元音：此時 op 還沒有（否則是規格錯誤），w ＝ L · r · R。r 含元音，所以 w 的首輔音是 L · 首輔音(r)，插入點正是 r 的首輔音之後，也就是 op ＝ <x> 在 r 上的位置：w′ ＝ L · <x>(r) · R。

只有最後一種情形與 r 的內容有關，而它正是把中綴交給 op、在詞根上決定位置的情形。∎
</details>

測試以隨機的詞素序列 × 元音開頭、輔音開頭的詞根檢查這個引理，直接套用的定義只有十幾行，寫在測試裡（`test/fuzzy/grammar.test.js`）。

### 4.4 展開、順序與上限

- **展開**：每條組合規則的每一種同位詞素選擇各一項（笛卡兒積）。AF.IRR 有 4 種：m、mu、mi、me。
- **順序**：自由詞素在前（依規格順序），組合規則在後（依規格順序）。rank 記下這個順序（2.4 節）；同一個選擇產生的兩項（2.3 節）rank 相同。
- **上限**：展開後超過 5,000 項是規格錯誤，通常是同位詞素很多的詞素出現在很多組合規則裡。
- **形式正規化**：詞綴先經過語言設定檔的正規化（與搜尋鍵相同），中綴的插入點看的是正規化後的元音。

### 4.5 巴宰語展開的結果

巴宰–噶哈巫語的設定檔有 74 個詞素（其中 5 個 `free: false`：HORT、HORT.aw、KA.UV、AF.m、AF.C）、18 條組合規則，展開成：

| 項目 | 數量 | 其中由組合規則產生的 |
|---|---|---|
| 前綴 | 66 | minu、mini、mine、mina、kina、pina |
| 後綴 | 6 | — |
| 中綴 | 2 | — |
| 重疊 | 6 | — |
| 包覆單位（`circumfixes`） | 23 | 全部 |

23 個包覆單位中，新增的形狀有：

| 組合規則 | 包覆單位 | 串接的一項（`stemInitial: 'V'`） |
|---|---|---|
| AF.PFV（m ＋ <in>） | (m, <in>, ∅) | min- |
| AF.PROG（AF.m ＋ <a>） | (m, <a>, ∅) | ma- |
| AF.IRR（AF.m ＋ <a> ＋ -ay） | (m, <a>, ay) | ma-…-ay |

- AF.PFV 引用 AF，其他三個形式（mu、mi、me）的中綴插在前綴裡，編成前綴 minu-、mini-、mine-。
- AF.PROG、AF.IRR 引用只有 m 的 AF.m，AF.IRR2（M-…-ay）引用只有 mu、mi、me 的 AF.C：資料中只有這些形式（language-profile.md 的編寫技巧第 1、2 項）。
- 原本的平面清單有 65 個前綴、7 個後綴、15 個環綴。

### 4.6 檢查展開結果

```js
import { expandGrammar } from 'babizu/fuzzy'

const flat = expandGrammar(profile.morphology)
console.table(flat.circumfixes.map((c) => ({ ...c, parts: c.parts.map((p) => `${p.id}=${p.form}`).join(' ') })))
```

`babizu check` 會驗證文法：欄位、重複的 id、不存在的詞素、每一種同位詞素選擇的推導（4.1 第 5 項），以及展開的上限。

## 5. BCDP 的改動

以原版 BCDP（bcdp.md）為基礎，只有下面幾處。沒有條件分類、沒有沿路徑的 DFA、沒有多目標通道、沒有懲罰。

### 5.1 (L, op) 的起點

- 原版的還原變體，詞幹起點 i 的成本取自前綴鏈合併後的狀態 P（bcdp.md 第 6 節）。
- 外側有 L 的中綴、重疊用法，改取「前綴鏈 · L」在 i 結束的成本。
- 這個量原版已經在算：它就是前綴式環綴左邊 ℓ ＝ L 的狀態 P_ℓ（bcdp.md 第 5 節「環綴的兩側」）。實作上只是把 `P.row[i]` 換成 `circ.P.get(L).row[i]`，起點仍是固定的交界。
- 說明時以 `metric.traceSegment` 在 L 上追回外面的前綴鏈，與前綴式環綴相同（bcdp.md 第 8 節）。
- 沒有 R 的包覆單位，詞尾照一般的後綴鏈處理（接 S，或就是詞尾）。
- 同一個位置、同一種拿法、同一個 L 的變體，仍共用一個通道（bcdp.md 第 6 節）。

### 5.2 詞根元音開頭：併進同後綴的通道

`stemInitial: 'V'` 的前綴式環綴，詞尾與同後綴的通道完全相同，差別只在「只接以元音開頭的詞根」。所以它們不另建通道，而是成為那個通道對元音開頭的詞的另一個起點（bcdp.md 第 7 節）：

- `FuzzyIndex.searchChannels` 的通道多一個選項 `initialFrom: { initials, from }`：第一個字元在 `initials` 中的詞改由 `from` 出發。
- 第 0 列只由起點決定，所以根節點算好兩套第 0 列，走進每條邊之前依邊的字元換上其中一套；之後的列都由第 0 列算出，照常計算。
- 以元音開頭的詞的起點是「原本的起點 ∪ 環綴的起點」（定理 2），逐格記著來源；說明時由它追溯一次，那一格的來源就是答案。
- 有後綴的，併進同後綴的前綴式環綴通道；沒有後綴的，併進「接在前綴之後」的通道（沒有那個通道時另建一個，只走元音開頭的詞）。
- 這是精確的：每一類詞得到的仍是各自的最小成本。與另建通道相比，詞圖中元音開頭的那一部分只走一次。

### 5.3 同分規則

2.4 節的順序在每一個取 min 的地方套用。它只改變「同分時記下哪一個來源」（tag），不改變 min 本身：

| 地方 | 原版 | 這一版 |
|---|---|---|
| 同一層詞綴 trie 的合併（`mergeInto`） | 保留先合併的（trie 走訪順序） | 同分時保留 rank 較前的 |
| 前綴式環綴依後綴分組的起點 | 保留先合併的 | 同分時保留 rank 較前的 |
| 共用通道的還原變體，詞尾選哪一個步驟 | 先產生的 | 同分時選 rank 較前的 |
| 不同通道的同一個詞根（`finish`） | 先找到的通道 | 步驟少的，再依各步驟的 rank 由小到大比較 |
| 元音開頭的環綴併進原本的起點（5.2 節） | — | 步驟少的（前綴鏈的層數對環綴的 1），一樣多時依 rank |

各層之間「較少詞綴的鏈優先」（bcdp.md 第 11 節）不變。

### 5.4 證明與停止性

- 原版的定理 1（交界狀態充分）、定理 2（合併）、定理 3（剪枝）不變。
- **新增的引理**：
  - 陳述：L 那一側狀態的第 i 格 ＝ min over 前綴鏈 π（0 ≤ |π| ≤ `maxSteps`）｛c(π) ＋ E_J(q[0..i), π · L)｝。
  - 理由：這正是前綴式環綴使用的量，由定理 2 得到，也已經有測試。
  - 推論：(L, op, R) 的變體，列舉的就是所有 π · L · op(t) · R · σ 形式的分析，詞幹起點固定在 i；i 逐一試過所有有限的位置。bcdp.md 第 9 節的正確性第 2 項因此涵蓋新的形狀。
- **`stemInitial`**：5.2 節的篩選是精確的，而串接那一項只是一般的前綴式環綴。
- **同分規則**：只影響 tag，min 的值不變，所以成本與原版逐位元相同（第 7 節的快照）。
- **停止性**：
  - 變體數 ≤ 位置數 × 用法數，外側 L 的種類有限；
  - 鏈長 ≤ `maxSteps`；
  - 詞圖是有限的 DAG。

  所以 BCDP 一定會停止，而且沒有新的迴圈。

### 5.5 分析器

`createAnalyzer` 的 `analyze`、`generate` 都加上外側的 L；`stemInitial` 的項目只接元音開頭的詞根。
查詞根找衍生詞（自動派生）改由建置時的自動派生圖處理（bcdp.md 第 10 節），直接用 BCDP 的結果，不再經過分析器。

## 6. 拿掉了什麼、為什麼

前一版（2026-09-27）的文法有同位詞素條件、未收錄組合的懲罰，以及第二個實作（類 pika 的加權剖析器）當仲裁者。git 歷史保留在 babizu 的 b018a2a、f43e744、adb9287。拿掉的理由都來自資料：

| 拿掉的 | 代價 | 效果（全部 2,141 組詞對） |
|---|---|---|
| 同位詞素條件（`when`，受限正規表達式編成 DFA）與 `conditionPenalty` | 約 900 行，包括 DFA 沿詞圖路徑前進、交界狀態依條件分類、每個通道多個詞尾目標；構詞搜尋 ＋57% | 條件的懲罰決定最佳分析的次數：0。AF 設條件反而讓拆解完全正確率由 53.1% 降到 49.7% |
| 自動產生的未收錄組合與 `unattestedPenalty` | 每個前綴 × 每個中綴，前綴單位由 65 個變成 180 個 | 決定最佳分析 12／1,977 次（0.6%），其中排第一的 6 次。其中 kina- ＋ tu- 這類，改成「只有一側的組合規則是一般詞綴」之後照樣找得到 |
| 類 pika 的剖析器（`chart.js`）與搜尋方法切換 | 中位數 100 ms、p95 405 ms；單元測試約 200 秒 | 只用來仲裁 BCDP |
| 正規表達式原型（`regex.js`） | — | 只是探討，沒有用在搜尋 |
| `maxUses` | — | 只檢查組合規則的序列，對搜尋沒有作用 |

另外也拿掉了：

- 搜尋引擎的 `morphMethod`、站台設定 `search.morphology`、設定選單的切換；
- 說明中的「未收錄的組合」「條件不成立」標籤。

**為什麼不需要仲裁者**：

- 仲裁者存在的理由，是前一版的 BCDP 改動很大（條件分類、多目標），需要一個獨立的實作來驗證。
- 這一版的 BCDP 只多了 5.1–5.3 節的改動，每一處都是原版既有的量或只改 tag。
- 驗證由原版就有的窮舉參考實作負責（`test/fuzzy/reference/ref-morph.js`，只在測試中使用），它已擴充到新的形狀（第 7 節）。

**保留的**：

- `parts` 的標註與說明中的詞素列表；
- 詞條家族；
- 拆解正確率的評估工具；
- 平面清單的隨機規格產生器。

## 8. 已知限制

- **重疊只能是推導的第一步**：「先加前綴、再重疊前綴的材料」不支援，是規格錯誤。先重疊、再加前綴的（sa- ＋ CV~詞根）可以。
- **一個推導只有一個詞根上的運算**：兩個都落在詞根上的中綴（或中綴加重疊）是規格錯誤。
- **包覆單位緊貼詞根**，一個分析至多一個（與原版的環綴相同）。
- **同位詞素的選擇不檢查**：mi- 接在第一個元音是 u 的詞根上，成本與 mu- 相同。資料中有大量反例（mu-aping、mu-axay），硬性條件會是錯的；懲罰又從來沒有決定過分析（第 6 節）。
- **組合規則展開每一種同位詞素選擇**，不論資料中有沒有出現。構式只用其中幾個形式時，另寫一個 `free: false` 的詞素只列那幾個，組合規則引用它（language-profile.md 的編寫技巧第 1 項；巴宰語的 AF.m、AF.C）。
- **同分規則是逐點的**（2.4 節），只影響標註。不同詞根同分時依字典序排列：例如 maatabilih 的 maa- ＋ tabilih 與 <a> ＋ matabilih 同分，排在前面的是 matabilih。
- **引理假設詞根含元音**：沒有元音的詞根上，首輔音會延伸到詞根之外。這種詞根實際上幾乎不存在，不另外處理。
