# 展示版（playground）

展示版讓人**不用安裝任何東西、不用寫程式**，在瀏覽器裡把自己的詞表與方言規則變成一部 Babizu 辭典：
- 上傳或貼上詞表（CSV、TSV、Excel），在網頁上直接編輯；
- 寫方言之間的語音對應與詞綴；
- 按「建置」，瀏覽器在幾秒內建好資料；搜尋、詞條、資料來源、演算法實驗室都換成這份專案。

它和語言無關。第一次開啟時是範例專案：巴宰語與噶哈巫語的幾十個詞與例句（出處寫在每一列的備註），方言規則取自巴宰–噶哈巫語辭典最早的語音對應規則。
讀入完整的詞表時，它就是一部完整的辭典；也可以把成果匯出成正式站台的檔案。

- 網址：<https://babizu.github.io/babizu/>（框架 repo 的 GitHub Pages）
- 本機：在框架目錄 `npm run playground`（開發伺服器）或 `npm run playground:build`

## 1. 工作坊流程（參加者不必會 git 或程式）

1. 開網址，按頂端的「工作台」。
2. **詞表**分頁 → 「匯入」：
   - 選檔案（.csv、.tsv、.xlsx），或在試算表選取範圍、複製、貼上；
   - 第一列可以是表頭。表頭是「詞、中文、英文、方言、詞類、其他寫法、備註」（中英文都認得）時自動對應，
     否則每一欄自己選用途；
   - 方言欄可以寫變體的代碼或名稱，可以有好幾個（以逗號、頓號、斜線分開）。對不到的值可以自動新增為語言變體；
   - 選「附加」或「取代」。
   也可以按「新增一個詞」直接輸入。
3. **專案**分頁：
   - 改辭典名稱；
   - 整理語言變體：代碼、名稱、上層（例如海岸腔屬於南部）、顏色。
4. **方言規則**分頁：每條規則是「寫法 A ↔ 寫法 B」，權重越小越便宜。
   - 有系統的對應寫 0.1，偶爾才有的寫 0.2–0.3；
   - 目標留空表示「脫落」；
   - 可以限定詞首、詞尾。
5. **構詞**分頁：
   - 列出前綴、後綴、中綴；
   - 勾選重疊型式；
   - 填構詞音變（只在詞素交界發生的變化）。
6. 按「建置」：頁面重新載入，下方顯示建置進度。
7. 回到「搜尋」，打一個方言的寫法，看其他方言的詞是不是也找得到。
   - 結果旁的標籤點開，可以看「為什麼找到」；
   - 「演算法實驗室」（關於頁有連結）一步一步看動態規劃表、詞圖搜尋與 BCDP 構詞分析。
8. 結束前：在**專案**分頁按「匯出專案檔」，把檔案帶走。下次「匯入專案檔」就能繼續。

## 2. 資料存在哪裡

- 專案只存在這台電腦的這個瀏覽器裡（IndexedDB），**不會上傳到任何地方**。
  - 工作台正在編輯的是「草稿」：自動存檔，重新整理不會不見；
  - 網站顯示的是最後一次建置的專案；
  - 「放棄變更」讓草稿回到最後一次建置的內容。
- 清除瀏覽器的網站資料、或用無痕視窗，專案就沒了：要保留請匯出專案檔。
- 換一台電腦、換一個瀏覽器，都是各自的專案。

## 3. 匯出

| 按鈕 | 內容 | 給誰 |
|---|---|---|
| 匯出專案檔 | `<名稱>.babizu.json`：整份專案（詞、例句、變體、語言設定檔） | 自己或其他工作坊參加者：下次匯入繼續 |
| 匯出網站起始包 | zip：`babizu.config.js`、`language.json`、`data/`（標準資料集）、README | 網站維護者：放進一個新的站台 repo，`npx babizu build` 就是同一部辭典（[getting-started.md](getting-started.md)） |

起始包的資料集是一個來源（`playground`）、詞與例句兩個分片。要接上真正的原始資料（試算表、辭典檔），
改寫一個轉接器（[adapters.md](adapters.md)）。語言設定檔可以照用。

## 4. 運作方式（給開發者）

展示版是同一個前端的一種模式，不是另一套程式。

- **站台設定**：`babizu.config.js` 寫 `playground: { sample: '範例專案.json' }`（[site-config.md](site-config.md)）。
  - 這種站台建置時不讀資料集，只把範例專案放進網站（`playground/sample.json`）；
  - 語言設定檔可以省略，用範例專案的；
  - 不提供對應組檢索。
- **執行期的站台設定**：
  - 前端的 `virtual:babizu/site` 是 `export default await loadPlaygroundSite(建置時的設定)`（`app/src/playground/runtime.ts`）；
  - 它從 IndexedDB 讀最後一次建置的專案（沒有就讀範例），產生站台設定：名稱、語言變體與顏色、語言設定檔、範例、實驗室的預設輸入；
  - 介面字串、語系沿用建置時的設定；
  - 前端其他模組都在它之後才執行，所以照常把站台設定當常數用。換專案就重新載入頁面。
- **在瀏覽器建置**：
  - 專案先轉成標準資料集（`src/playground/project.ts`），再用與 `babizu build` 同一份程式產生網站資料（`src/site/site-data.ts`）；
  - 構詞分析分給幾個 Web Worker 平行跑（`app/src/workers/build.worker.ts`、`derive.worker.ts`）；
  - 結果存進 IndexedDB，以專案內容與前端的建置代號為鍵：沒變就不重建，框架改版後重建一次；
  - 頁面讀資料（`app/src/services/data.ts`）與搜尋 Worker 都改從 IndexedDB 讀同樣路徑的內容。
- **等價**：同一份資料，瀏覽器建出的網站資料與 Node 端逐位元相同。
  - 單元測試比對 Node 的 worker_threads 與單一執行緒的分析（`test/playground/project.test.ts`）；
  - 實際在瀏覽器建一份 5,746 個詞形、有構詞文法的專案，版本雜湊也與 Node 的相同。
- **規模**：
  - 上述的專案（巴宰–噶哈巫語網站已公開的詞形）在 16 執行緒的電腦上，建置加第一次搜尋約 6 秒；
  - 單一執行緒約 17 秒；
  - 網站資料約 4.6 MB（存在 IndexedDB）。
  沒有構詞時幾乎是立即的。
- **匯入的格式**：
  - CSV 依 RFC 4180；
  - .xlsx 讀第一張工作表（共用字串、行內字串、數字），以瀏覽器內建的 `DecompressionStream` 解壓；
  - 匯出的 zip 不壓縮。
  - 都不加套件（`src/playground/tabular.ts`、`xlsx.ts`、`zip.ts`）。

## 5. 限制

- 每個專案只有一個資料來源；沒有音檔、掃描圖、分組（詞條家族的標註）。
- 構詞分頁只編輯平面清單（前綴、後綴、中綴、重疊、構詞音變）。
  構詞文法（morphemes、constructions）與其他欄位在「進階」分頁以 JSON 編輯。
- 實驗室的 DP 與詞圖分頁可以即時試改規則；BCDP 構詞分頁用的是最後一次建置的規則與構詞規格。
- 不提供對應組檢索（它的模型要用 LingPy 離線學習，見 [csr.md](csr.md)）。
- 瀏覽器不允許 IndexedDB 時（某些隱私模式），每次開啟都從範例專案開始，也不能建置自己的專案。
