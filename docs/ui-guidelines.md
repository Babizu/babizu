# 介面設計規範

框架的前端（`app/`）使用 Vue 3＋shadcn-vue（new-york-v4 樣式，以 reka-ui 為基礎）＋Tailwind CSS v4。本文件記錄一致性規則，修改框架的頁面或元件時請遵守。

## 設計語言：工具書，不是產品官網

這是一個資訊密度高、需要久讀的查詢工具。版面基調取自紙本辭典與學術工具介面，
刻意避開目前生成式工具的預設外觀（大圓角卡片＋柔和陰影＋紫藍漸層＋Inter），
因為那套視覺語彙是為稀疏的行銷頁設計的，用在密集的詞條列表上只會讓層次消失。
四條規則，新元件一律照辦：

1. **圓角小。** 基準 `--radius: 3px`，全站只有三階（`rounded-sm` 2px／`rounded-md`、`rounded-lg` 3px／`rounded-xl` 4px）。
   圓角要配合密度：密集的列表用小圓角才顯得精準。`rounded-full` 只留給真正是圓點或藥丸的東西
   （計數泡泡、狀態圓點、滑桿把手、播放鈕），不要拿來做晶片或卡片。
2. **深度靠界線，不靠陰影。** 卡片、輸入框、按鈕、分頁一律是 1px 髮絲線加底色，**沒有陰影**。
   陰影只用在真正浮起來的圖層：對話框、抽屜、彈出層、工具提示。
   不要同時用兩種深度提示做同一件事（浮層保留邊框是為了深色模式下看得見邊界，這是唯一的例外）。
3. **不用漸層**，不用色塊當裝飾。顏色要有意義（方言、狀態、命中）。圖示也一樣：只放在它真的增加資訊的地方
   （播放、返回、複製）。已經有文字或符號表達的意思不再加圖示——模糊命中的晶片有「≈」就夠了，
   不要再加閃光（sparkles）這類泛用的「AI」圖示。
4. **字體分工**：襯線體＝目標語言與刊頭，無襯線體＝介面。見下節。

## 設計 token

定義在 `app/src/assets/main.css`，淺色與深色各一組。**不要在元件裡寫死顏色**，一律使用語意化的類別。

| 用途 | 類別 |
|---|---|
| 頁面、卡片、浮層背景 | `bg-background`、`bg-card`、`bg-popover` |
| 主要文字、次要文字 | `text-foreground`、`text-muted-foreground` |
| 主色（深靛藍）：主要按鈕、連結、最佳路徑 | `bg-primary`、`text-primary` |
| 強調底色（淡靛藍）：語音規則、目前項目 | `bg-accent`、`text-accent-foreground` |
| 邊框 | `border`（預設即 `border-border`） |
| 搜尋命中高亮 | `<mark>`（已套用 `--mark` 色） |
| 校對狀態 | `StatusBadge`：未校對＝紅、初步校對＝黃、二審校對＝綠 |
| 語言變體色 | `.variety-<代碼>` 提供 `--variety-fg`／`--variety-bg`（由站台設定產生，見下） |
| 髮絲線面板 | `.panel`（＝`bg-card border rounded-md`，不加陰影） |
| 編輯操作（演算法實驗室） | `bg-op-substitute`、`bg-op-delete`、`bg-op-insert`（各有 `-foreground`）；一律搭配符號 ≠ − ＋，不單靠顏色 |

語言變體（方言）的顏色由站台設定決定（`varieties[].hue` 或 `colors`），建置時寫進 `index.html`，淺色與深色各一組。
下層變體（`parent`）用上層的同色相、較低彩度，表達從屬關係——篩選上層時下層會一併出現。
元件只透過 `DialectBadge` 使用；站台的 Markdown 內容用 `.variety-badge.variety-<代碼>`。**框架程式裡不能出現任何變體代碼。**

## 字體與文字

字體有明確分工，不要混用：

| 用途 | 字體 | 類別 |
|---|---|---|
| 目標語言的詞形、音標 | Gentium Book Plus（SIL 為語言學出版設計的襯線體） | `.native-text` |
| 頁面主標題、刊頭、統計數字（含資料來源卡片裡的小統計） | 同上 | `font-serif`，數字另加 `tabular-nums` |
| 介面文字、中文 | 系統無襯線體 | 預設 |

選 Gentium Book Plus 的理由：目標語言是網站的主角，值得有自己的字體；
而且它的 latin-ext 子集完整涵蓋語言學資料常用的音標與附加符號（`ə ʔ ŋ ɨ ā é ū́`），
換成一般 UI 字體會在國際音標資料上出現字形替換。
各子集都有 `unicode-range`，瀏覽器只下載實際用到的部分。

- 目標語言的文字加 `.native-text`：套用襯線體，並允許在任意位置斷行，避免長詞在手機上撐破版面。
- 中文釋義加 `.gloss-zh`，行高較寬。
- 層級：
  - 詞條頁標題 `text-4xl`／`sm:text-5xl`
  - 搜尋結果詞形 `text-lg font-semibold`
  - 釋義 `text-[15px]`
  - 出處 `text-xs text-muted-foreground`

演算法實驗室另有自己的設計規格：[lab-design.md](lab-design.md)（一個強調色只給最佳路徑與目前焦點、逐步播放、鍵盤操作）。

## 資訊呈現順序

每一筆結果（搜尋列、詞條頁）都依這個順序排列：

1. **詞形**（最顯眼）＋方言徽章＋屬性標籤（`MetaTag`）＋模糊命中說明（`MatchExplanation`）
2. **釋義**：中文在前，英文、臺語以次要色接在後面
3. **出處**：來源簡稱 · 出處說明（`ResultCitation`）
4. 播放鈕固定在右側、垂直置中

### 例句（搜尋結果）

- 句子在最上面（命中的詞以高亮標出），下面是翻譯，最下面一列是方言、命中說明、出處。
- 命中說明與詞條用同一個元件（`HitTags`）：
  - 自動派生、自動拆解是可以點開的說明（`MorphologyExplanation`）；
  - 句中的詞與查詢有辭典的構詞關係時，是身分標籤「確定派生 usa」「確定拆解…」「確定同根…」（`MetaTag`，停留時說明是辭典標註、不是演算法推定的）；
  - 模糊命中是 ≈ 對齊標籤（`MatchExplanation`）；
  - 開頭相符、包含是文字標籤。
- 多詞查詢時每個查詢詞一組標籤，前面用次要字色寫出句中命中的詞。
- 自動派生經過其他詞時（上一層本身也是自動派生的）：
  - 標籤仍只寫最後一層（「pusungut ＋ ‹a› ＋ -ay」）；
  - 上面幾層在彈出框裡逐層列出（「pusungut ＝ pu- ＋ sungut」），每層附成本。

### 標籤的用語：辭典標註與自動推定分開

演算法推定的關係一律冠上「自動」，資料來源寫明的關係冠上「辭典：」或用詞條家族的縮排表示，兩者不混用（[concepts.md](concepts.md)「辭典標註與自動推定」）：

| 標籤 | 來源 | 元件 |
|---|---|---|
| 自動拆解：mu- ＋ daux | 演算法（BCDP）去掉詞綴 | `MorphologyExplanation`（彈出框標題「自動拆解的說明」） |
| 自動派生：p‹a›u- ＋ sungut ＋ -ay | 演算法推定由查詢加上詞綴而來 | `MorphologyExplanation`（彈出框標題「自動派生的說明」） |
| 自動同根 bubuer | 演算法推定與查詢來自同一個詞庫外的詞根 | `MorphologyExplanation`（彈出框分列查詢的拆解、詞庫外的詞根、這個詞的衍生；沒有實驗室連結） |
| 確定派生 usa | 辭典標明衍生自查詢、或列在查詢的條目下 | `MetaTag`，`title` 說明不是演算法推定的 |
| 確定拆解 pinakita | 查詢列在這個詞的條目下（這個詞是上層） | 同上 |
| 確定同根 kita- | 與查詢列在同一個詞（後面的詞）底下 | 同上 |
| 另立條目、詞條家族的縮排 | 辭典的條目結構 | `EntryRow`、`EntryTree` |

- 自動的說明結尾一律寫「此為演算法…不是辭典的標註／並非確定的分析標註」，並連到演算法實驗室重現同一次計算
  （自動拆解：查詢 → 詞根；自動派生：這個詞 → 上一層，就是建置時算的那一次）。
- 新增標籤時先決定它屬於哪一欄；屬於自動的，名稱必須帶「自動」，屬於辭典的，名稱帶「確定」。
- 兩欄的外觀也分開，不必讀字就分得出來：
  - 自動拆解、派生、同根是**虛線外框**（Badge 的 `inferred` 變體）；
  - 確定派生、拆解、同根是**實心淡底**（`soft`），前面一個書本圖示。
  - 彈出框標題旁也有同樣虛線的「演算法推定」標記。各項成本靠右對齊，最後一列是合計（排序用的成本），免責說明放在淡底的提示框裡。

### 搜尋方法（篩選面板）

`FilterPanel` 的「搜尋方法」一節，與上面的標籤同一套分類，四組：拼寫（完全相符、相近拼寫）、部分符合（開頭、結尾、包含）、
確定（拆解、派生、同根）、自動（拆解、派生、同根）。

- 每組一列：整組勾選框（全選、全不選、部分三種狀態）、組名與來源（「確定」旁以次要字色寫「辭典標註」）、整組的筆數、展開鈕。
  - 整組的筆數是組內各方法的**聯集**（搜尋回應的 `methodGroups`），一筆記錄同時屬於組內好幾種方法時只算一次，不是相加。
- 個別的方法收在組底下，**預設收合**，展開鈕（`aria-expanded`）切換：
  - 一開始就部分排除的組（例如網址帶 `x=prefix`）展開，讀者看得到排除了哪幾個；
  - 收合的組如果部分排除，組名下面寫「不含 開頭」；
  - 收合用 `grid-template-rows` 做高度動畫（`prefers-reduced-motion` 時不動），收合後 `inert` 加 `visibility: hidden`，鍵盤與輔助技術都不會進到看不見的選項。
- 展開後個別的方法縮排在一條細線右側，右邊留出展開鈕的寬度，筆數（等寬數字）與整組的筆數對齊；筆數為 0 的選項用次要字色。
  筆數不受排除影響，看得到排除掉的方法有多少。
- 有排除時，標題旁出現「全部顯示」；「清除篩選」也一併恢復。排除記在網址 `x=`，行動裝置的篩選鈕計數也算進去。
- 組名寫明來源：「確定」「辭典標註」、「自動」「演算法推定」，與結果中的標籤用語一致；整組勾選框的無障礙名稱是「整組：確定（辭典標註）」。

### 句型搜尋（搜尋結果）

查詢用到句型的寫法時（[pattern-query.md](pattern-query.md)），結果區換成句型搜尋：

- **模式列**：結果上方一行。
  - 「以句型搜尋」用虛線框，與「自動」標籤同一種外觀：這是依寫法自動判斷的；
  - 「改用一般搜尋」（網址 `m=plain`）；
  - 「句型的寫法」連到關於頁的 `#pattern`。
  - 被強制以一般搜尋、查詢又有句型寫法時，一般搜尋的結果上方提示可以切回來。
- **語法錯誤**（`PatternError`）：
  - 等寬字顯示查詢，出錯的範圍畫波浪底線；
  - 下面是說明與建議（最接近的詞綴、`pa*` 改寫成 `pa…`）；
  - 一定附「改用一般搜尋」，因為自動判斷可能誤判。
- **提示**（`mo-` 視為 `mu-` 等）：結果上方，左側一條細線，次要字色。
  帶改寫的提示（`W_INNER_AFFIX`：列出的詞綴只算最外層，改寫成 `…-x-…` 多找到幾個詞形）在說明後面接一個連結「改查 `…-x-…`」，
  保留模糊程度與篩選，分頁回到記錄。
- **三個分頁**，網址記在 `tab`：
  - **記錄**（`records`；`PatternHitItem`）：
    - 依語言單位分成三區：詞條（詞綴與詞的條目）、片語、句子（引擎的 `PATTERN_GROUPS`），
      每區一個標題（名稱＋筆數），與一般搜尋的區塊標題相同；各區各自「顯示更多」；
    - 兩區以上有命中時，上方一排分區標籤（全部、詞條、片語、句子，附筆數）可以只看一區，選中的用 `bg-accent`；
    - 命中的詞依引擎回傳的位置高亮，不在介面重新切詞；
    - 寫出條件的詞用一般的高亮，`_` 與 `!x` 比到的詞用較淡的底色；
    - 下面每個有說明的詞一組 `HitTags`（自動是虛線框、確定是實心底），拼寫完全相同的不必說明。
    - 構詞樣式比到的不是這個詞最好的拆法時，「自動拆解」標籤後面加「· 次佳」，說明中寫出最好的與這一種的成本；
      詞根是虛擬詞根時說明它不在詞庫中，不連到實驗室（實驗室重現不了）。
  - **對照**（`PatternKwic`，語詞索引）：
    - 左文靠右、命中置中加粗、右文靠左，左右各截在詞的邊界；
    - 可以依原本的順序、左邊的詞、命中的詞、右邊的詞排序（`ks`）；
    - 窄螢幕（< sm）改成一般的一行文字。
  - **頻率**（`PatternFrequency`）：
    - 主條件每一格一張表：詞形、次數、句數，次數的長條沒有底色軌道；
    - 只有一種詞形的格，在上面一行列出（「ini 都是 ini」）；
    - 點一個詞形篩選句子與對照，篩選以可移除的小標籤顯示在分頁下方。
- 篩選面板在句型模式時不顯示「搜尋範圍」與「搜尋方法」，因為句型只比對族語，詞的條件由寫法決定。
- 關於頁的「句型搜尋」一節（`PatternGuide`）：
  - 寫法表用「詞」「詞綴」等代稱，框架不寫死任何語言；
  - 例子來自站台設定 `patternExamples`，點了以 `m=pattern` 搜尋；
  - 語言設定檔沒有構詞規格時，不列構詞樣式。

### 詞條家族（搜尋結果）

辭典確認屬於同一個詞條的命中排成一個區塊（`EntryGroupItem`；排序規則見 [fuzzy-search.md](fuzzy-search.md)）：

```
kita-  詞綴 / 詞根  自動拆解 pa- + kita          ← 詞條（家族的代表）固定在最上面，與一般結果列相同
巴宰語詞典 · p.152–153，kita- 條
│ pakita  完全相符  另立條目                    ← 子項目：精簡列，縮排＋左側細線表示「屬於上面那一列」
│ 給人看 to show it
│ │ pakita saw  片語  開頭相符                  ← 辭典中列在 pakita 底下的，再縮一層
│ │ pinakita  自動派生 pakita + <in>
│ kinita  另立條目
│ 再顯示 6 個相關項目                           ← 每層只先顯示前幾項（第一層 4、其下 3；只多 1 項時全部顯示）
```

- 只有一筆的家族與一般結果列完全相同，不加框、不縮排。
- 子項目不重複出處（與詞條相同）；另立的衍生條目只標「另立條目」，出處放在提示中。
- 寫法相同的另立條目併進辭典列出它的那一列，「另立條目」標籤本身是連到那個條目的連結。
- 本身沒有命中、只是為了看出上下層的列用次要字色，不加命中標籤；家族代表本身沒有命中時標「所屬詞條」。
- 完全相符的子項目標「完全相符」：單獨的結果列不需要，但在家族中讀者要看得出整個區塊是因為哪一列排上來的。
- 以詞根身分命中的子項目（辭典標註它衍生自查詢的詞根）不加命中標籤，說明已經在詞條那一列。

### 同形詞組（搜尋結果）

不同來源寫法完全相同的詞合成一項（`SpellingSetItem`；規則見 [fuzzy-search.md](fuzzy-search.md)）。
詞形只寫一次，底下每筆一列，比的是釋義：

```
matoway  ≈ 0.1 ura→owa 滑音產生  2 筆           ← 詞形＋共同的命中標籤＋筆數；與家族同一個標題尺寸
│ 唱歌，唱戲  臺：chhiùn-koa  噶哈巫              ← 每一列：釋義、方言
│ 噶哈巫分類辭典 · 《噶哈巫語分類辭典》11-007      ← 出處（整列連到那筆記錄）
│ 唱歌  噶哈巫
│ 潘德興詞彙表 · 第 257 列
│ 看見 to see  也列在 kita- 條下                  ← 家族中的同一個詞另外列一份，標明它在哪個家族
```

- 與詞條家族同一套語彙：左側細線表示「屬於這個詞形」，不加框。家族是辭典的上下層，詞組是跨來源的並列，
  兩者不混用：家族從不併進詞組，詞組裡也不展開家族。
- 命中標籤：每一筆都相同時只寫一次，放在詞形旁；不同時各寫在各自那一列。
- 附加符號不同的寫法不合併，各自單獨一項。

## 互動狀態

- **目前所在頁面**：頁首選單的目前項目用主色 2px 底線，壓在頁首的分隔線上（像紙本索引的書籤），
  另加 `aria-current="page"`；不要只靠字色深淺。
- **按鈕按下**：`active:translate-y-px`（下沉 1px），`prefers-reduced-motion` 時取消。不用放大、縮小或彈跳。
- **一串「值＋數字」**（例如搜尋結果上方的相近拼寫）：用 `flex-wrap` 的清單，每項 `whitespace-nowrap`，
  數字用小號的等寬數字，不用全形括號與頓號串接——全形括號在窄螢幕上會把一行拆得很碎。
  位置要固定（放在結果數下方），不要依內容長短在同一行左右跳動。

## 標籤：一個尺寸、同一條基準線

結果列標題旁的所有標籤（方言、屬性、命中方式、模糊命中與構詞說明的按鈕）都用 shadcn 的 `Badge`（或 `badgeVariants`）
的 `size="tag"`：高 20px、`rounded-sm`、11px 字、`leading-none`，只有顏色依用途不同：

| variant | 用途 |
|---|---|
| `variety` | 方言（顏色由 `.variety-<代碼>` 提供） |
| `muted` | 未知的方言代碼 |
| `quiet` | 低調的屬性（單位、比對身分）；外框、次要字色 |
| `soft` | 說明性的標記（語音規則、構詞）；淡主色底 |

- 標籤列用 `flex flex-wrap items-center`，讓標籤與詞形的中線對齊。
- 可以點的標籤（開 Popover）用 `<Badge as="button">`，不要另寫一套按鈕樣式。
- 標籤外面再包一層時（例如 `relative z-10`），那一層必須是 `inline-flex`：普通的行內 `<span>`
  會帶進自己的行高，把標籤往下推，與旁邊的標籤錯開。

整列可點擊的結果列（搜尋結果、句型結果、檢查清單、記錄頁的列）用 `v-card-link="路由"`（`app/src/lib/card-link.js`）：

- 整列可以點，列中的文字又能拖曳反白、複製。**不要**再用「標題連結的 `::after` 撐滿整列」：
  滑鼠按在列上任何地方都會落在連結上，拖曳變成拖出網址，釋義與例句都選不到。
- 點在列中的連結、按鈕上時交給它們；剛反白了文字時不開啟；Ctrl／⌘／Shift 點擊與中鍵在新分頁開啟。
- 標題仍是真正的連結（鍵盤、螢幕報讀、右鍵複製連結）；指令把列中的連結都設成 `draggable="false"`。
- 列加 `group`，標題用 `group-hover:underline`，滑過整列時標題畫底線，提示這一列可以點。
- 列內的按鈕（播放、說明）照常在事件中 `stopPropagation`。

## 檢查清單：兩欄對照、捲動載入

`/checklist` 是給校對者的工作頁（資料來自 `babizu/search` 的 `Checklist`，由搜尋 Worker 計算）：

- **例句中沒有詞條的詞**：每一列左欄是詞與例句（`native-text`，詞以 `<mark>` 標出），右欄是辭典中最接近的詞條，
  用與搜尋結果相同的 `HitTags`（點開看對齊或拆解）。兩欄在 `lg` 以上並列、中間一條髮絲線；以下上下排。
  最上面是依最接近的詞條猜的類別（`MetaTag variant="soft"`，前面帶符號 ≈ ＋ ～ ∅，不另加圖示）。
- **完全相同的詞條**：每組一個詞形標題，底下每筆一列，出處在左、釋義在右，縱向對齊，一眼看得出哪幾筆釋義一樣。
- **重複的例句**：與上面同一個元件（`DuplicateGroup kind="sentence"`），標題是整句（一般字級），比的是翻譯；
  範圍是所有來源（含語料），連續空白視為一個。同一來源內翻譯也相同的標「翻譯相同」。
- 三份清單以底線分頁切換（窄螢幕可橫向捲動）（與頁首選單同一種語彙）；篩選用晶片（選中＝主色實底），排序這種次要設定選中時只用淡底，不與篩選搶主色。
- 捲動載入（`useInfiniteList`）：哨兵元素接近視窗就載下一頁，另有「載入更多」按鈕給鍵盤使用者；
  分頁、篩選、排序都記在網址上。載入中顯示與列同形的骨架，失敗時顯示錯誤與重試。

## 選項清單的欄數：跟著容器走，不是跟著視窗走

`FilterPanel` 這種會出現在兩種寬度容器裡的元件（桌面 15rem 側欄／行動滿版抽屜），
**不要**用 `sm:`、`lg:` 這類視窗斷點決定欄數——視窗寬不代表元件寬。
改用容器查詢加 `auto-fill`，讓欄數自己長出來：

```html
<div class="@container">
  <div class="grid gap-x-4 grid-cols-[repeat(auto-fill,minmax(7rem,1fr))]">…</div>
</div>
```

欄寬下限依標籤長度選：短標籤（方言、語言單位、搜尋範圍）`7rem`，
長標籤（來源全名）`11rem`，長標籤再加 `truncate` 與 `title`。
這樣同一份標記在側欄裡是一到兩欄、在抽屜裡自動變成三欄，不必寫兩套。

**一個選項就佔一整列是錯的**：選項很短時會留下大片空白，也把清單拉得很長。

## 有順序的少數選項用刻度拉桿

像「模糊程度」這種**由弱到強、只有三四段**的設定，用帶刻度圓點的拉桿，不要用一排按鈕：
拉桿本身就表達了「這是一條強度軸」，按鈕則看起來像三個無關的選項。
刻度圓點要對準滑鈕真正停下來的位置（滑鈕中心只在半個滑鈕寬到「總寬減半個滑鈕寬」之間移動，
用 `calc` 算，不能用 `justify-between`），下方的文字標籤同時是可以點的快捷鍵。

## 響應式與觸控

- 斷點：`sm` 640、`md` 768（切換底部分頁列與頂端選單）、`lg` 1024（出現側欄）。
- 主選單只放三項（搜尋、資料來源、關於）；演算法實驗室由「關於」頁與搜尋結果的說明連入，檢查清單（給校對者）由「資料來源」頁的說明連入。
- 頁首右側只有一個「設定」按鈕（`SettingsMenu`，Popover）：外觀（淺色、深色、跟隨系統）與介面語言（兩個以上的語系時才出現），
  都用分段按鈕（`ToggleGroup`），一眼看完所有選項。不要在頁首另外放語言選單或日夜切換鈕。
- **搜尋頁就是首頁**（路由 `/`）。這是一本辭典，讀者一進來就是要查東西，不需要另做一頁行銷式首頁；
  沒有查詢字串時，搜尋頁的空狀態負責說明網站是什麼並給可以按下去的範例。
- 窄螢幕的搜尋條件用**文字按鈕「搜尋條件」**，不要用漏斗圖示——圖示沒有普遍共識，文字一看就懂。
- **觸控目標至少 44px**：按鈕 `h-11`／`size-11`，核取方塊列 `min-h-10`，範例按鈕 `min-h-11`。
- 行動裝置：
  - 主選單在底部（`MobileTabBar`），內容區保留 `pb-20`。
  - 篩選放在底部抽屜（`Sheet side="bottom"`）。
  - 站台設定了 `specialChars` 時，搜尋框下方**固定**顯示快捷字元列（一般鍵盤打不出來的字母）。
    不要做成「聚焦時才出現」：手指按在下方選項上時輸入框失焦、整列收合，
    版面上移會害使用者放開手指時點到別的項目。
  - 搜尋框關閉自動大寫與自動修正（避免目標語言的拼寫被改掉）。
- **不得水平溢出**：
  - 寬表格（動態規劃表）放在自己的 `overflow-x-auto` 容器內。
  - grid 欄位用 `minmax(0,1fr)`，flex 子項加 `min-w-0`。
  - 端對端測試會在每頁檢查 `scrollWidth ≤ innerWidth`。
- 內容只渲染一份：桌面側欄、行動裝置內嵌的同一內容（例如出處卡），用 `useMediaQuery` 決定位置，不用 CSS 隱藏重複的 DOM。

## 無障礙

- 圖示按鈕一律加 `aria-label`。
- 播放鈕有 `aria-pressed`，搜尋結果區有 `aria-live="polite"`。
- 載入中的區塊加 `aria-busy`。
- 深色模式：預設跟隨系統，可在設定中選淺色、深色或改回跟隨系統（存為 `light`／`dark`／`auto`）；`index.html` 在載入前套用，避免閃爍。
- 頁首有「跳到主要內容」連結。

## shadcn-vue 元件

`components/ui/` 是 shadcn-vue new-york-v4 的 **JavaScript 版**。官方 CLI 在 `typescript: false` 模式無法轉換 v4 元件，所以依官方原始碼手動移植，使用相同的 reka-ui 元件與樣式類別。

新增元件時照同樣的模式：

- 以 `defineOptions({ inheritAttrs: false })` 加上 `v-bind="$attrs"` 把屬性與事件轉給 reka-ui。
- 樣式類別放在 `<script>` 的常數中（避免類別字串裡的引號與模板衝突）。

## 文字一律經過 t()

介面上的每一段文字（包括 `aria-label`、`title`、頁面標題）都要經過 `t('中文原文')`；不在呼叫處寫出來的字串（對照表、路由標題）用 `msg('中文原文')` 標出。
中文直接寫在程式裡，英文譯文加進 `locales/en.json`（鍵是中文原文）。
站台可以覆寫任何字串，所以措辭要中性、不能假設特定語言或特定來源。詳見 [i18n.md](i18n.md)。
