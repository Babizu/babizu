# 演算法實驗室設計規格

> 像一本會動的演算法教科書：每一步只改變一件事，讀者隨時知道現在在看哪裡、為什麼是這個值。

這份規格約束演算法實驗室（`/lab`）的三個分頁：動態規劃表、詞圖搜尋，以及 BCDP（構詞搜尋）。全站的設計語言見 [ui-guidelines.md](ui-guidelines.md)，這裡只寫實驗室特有的部分；兩者衝突時以 ui-guidelines.md 為準。演算法本身見 [fuzzy-search.md](fuzzy-search.md) 與 [bcdp.md](bcdp.md)。

## 0. 設計判讀

**讀者**：

- 語言工作者、語言學研究者：想知道「為什麼查 `minudox` 會找到 `daux-`」，以及方言規則與詞綴清單寫得對不對。
- 語言設定檔的維護者：調整規則權重、詞綴，立刻看到效果。
- 開發者：理解演算法、除錯。

**進入的方式**：

- 從搜尋結果的「查看計算過程」連入，網址帶著要看的詞（`?a=…&b=…`，BCDP 分頁是 `?tab=bcdp&q=…&t=…`）。
- 從「關於」頁進入，看預設的例子。

**任務**：看懂一個值怎麼來的（DP 的一格、詞圖的一個節點、BCDP 的一個分析），而不是瀏覽大量資料。所以版面以「目前這一步」為中心：一個焦點、一句說明、其餘的淡化。

**三個旋鈕**（design-taste 的量表，1–10）：

| 旋鈕 | 值 | 意思 |
|---|---|---|
| 版面變化 DESIGN_VARIANCE | 3 | 沿用全站的版面與元件，不為實驗室另創風格 |
| 動態強度 MOTION_INTENSITY | 2–3 | 只有逐步播放造成的狀態變化；沒有入場動畫、沒有裝飾性動畫 |
| 資訊密度 VISUAL_DENSITY | 5（DP 表與詞綴各層表內 8） | 面板與說明是一般密度；表格內每格都是資料，密但每格都可讀 |

## 1. 視覺主題

- **風格**：學術工具書（與全站相同）。
- **關鍵詞**：精確、可追溯、逐步、克制、可重現。
- **調性**：教科書的例題頁，不是監控儀表板或行銷頁的「互動展示」。
- **互動層級**：L2（流暢的互動，只用 CSS 過渡；不引入動畫函式庫）。

## 2. 色彩與角色

**全部使用 `app/src/assets/main.css` 的語意 token**，元件裡不寫任何顏色值或 Tailwind 調色盤顏色（`amber-500`、`emerald-700` 之類）。

**一個強調色**：主色（深靛藍 `--primary`）只給兩種東西：

1. **最佳路徑／最佳分析**：實心 `bg-primary text-primary-foreground`。
2. **目前焦點**（播放中的那一格、選取的格、目前走訪的節點）：`ring-2 ring-inset ring-primary`，不填色。

這兩者可以同時出現在同一格（最佳路徑上的目前格）：填色加一圈 `ring-primary-foreground`。

| 角色 | 類別 | 說明 |
|---|---|---|
| 一般格、面板 | `bg-card border` | 髮絲線，不加陰影 |
| 成本熱度 | `color-mix(in oklch, var(--muted-foreground) 0–22%, transparent)` | 值越大越深；只表達大小，不表達好壞 |
| 經由方言規則得到的值 | `color-mix(in oklch, var(--accent) 40–70%, transparent)`、`text-accent-foreground` | 與全站「語音規則＝淡靛藍」一致 |
| 尚未計算 | `text-muted-foreground/40`，顯示「·」 | |
| 剪枝的節點、略過的切法 | `text-muted-foreground` ＋ 文字原因 | 不用紅色：剪枝不是錯誤 |
| 詞綴段、詞幹段（BCDP） | 詞綴 `bg-muted`，詞幹 `bg-accent` | 最佳分析的詞幹改為實心主色 |

**操作類型**（對齊條、候選轉移列表）以**符號為主、顏色為輔**，新增三個低彩度 token（淺色與深色各一組）：

```css
:root {
  --op-substitute: oklch(0.94 0.035 85);
  --op-substitute-foreground: oklch(0.32 0.05 80);
  --op-delete: oklch(0.94 0.03 25);
  --op-delete-foreground: oklch(0.35 0.07 25);
  --op-insert: oklch(0.94 0.03 230);
  --op-insert-foreground: oklch(0.33 0.06 235);
}
.dark {
  --op-substitute: oklch(0.32 0.04 85);
  --op-substitute-foreground: oklch(0.93 0.04 85);
  --op-delete: oklch(0.32 0.05 25);
  --op-delete-foreground: oklch(0.93 0.04 25);
  --op-insert: oklch(0.32 0.04 235);
  --op-insert-foreground: oklch(0.93 0.035 235);
}
@theme inline {
  --color-op-substitute: var(--op-substitute);
  --color-op-substitute-foreground: var(--op-substitute-foreground);
  --color-op-delete: var(--op-delete);
  --color-op-delete-foreground: var(--op-delete-foreground);
  --color-op-insert: var(--op-insert);
  --color-op-insert-foreground: var(--op-insert-foreground);
}
```

| 操作 | 符號 | 底色 |
|---|---|---|
| 相同 | `＝` | 無 |
| 方言規則 | `≈` ＋ 分類名稱 | `bg-accent` |
| 替換 | `≠` | `bg-op-substitute` |
| 刪除（查詢多打） | `−` | `bg-op-delete` |
| 插入（查詢少打） | `＋` | `bg-op-insert` |

色盲或列印成黑白時，只看符號也能分辨。

## 3. 字體

沿用全站的分工（ui-guidelines.md「字體與文字」），實驗室另外規定：

| 用途 | 樣式 |
|---|---|
| 頁面標題 | `font-serif text-3xl font-bold tracking-tight` |
| 分頁內的面板標題 | `text-sm font-semibold` |
| 目標語言的字元、詞、詞綴 | `.native-text`（Gentium Book Plus） |
| 所有數值（距離、成本、索引） | `font-mono tabular-nums`；距離一律用 `formatDistance` |
| 表格內的格值 | `font-mono text-xs tabular-nums` |
| 格角的索引、箭頭 | `text-[9px]`，`opacity-60` |
| 步驟說明 | `text-sm leading-relaxed`，一句話 |

空白字元顯示為 `␣`，空字串顯示為 `ε`（DP 表頭）或 `∅`（規則）。

## 4. 元件

### 播放控制 `PlaybackControls`（新，三個分頁共用）

```
[⏮ 重來] [◀ 上一步] [▶ 播放／⏸ 暫停] [下一步 ▶] [⏭ 結尾]   ──●────────  37 / 120   速度 [1×▾]
```

- 按鈕沿用 `Button variant="outline" size="sm"`；觸控裝置（`pointer-coarse`）高度 44px。
- 進度拖曳用全站的 `Slider`，給 `thumb-label`（「步驟」）與 `thumb-value-text`（「第 37 步，共 120 步」）。
- 速度：0.5×、1×、2×、4×（原生 `<select>`）；1× 為每步 600 ms。
- 狀態：播放中 `aria-pressed="true"`；在第一步時「上一步」與「重來」停用，在最後一步時「下一步」與「結尾」停用（`disabled`，不隱藏）。

### 步驟說明 `StepNote`

- 一句話說明目前這一步做了什麼、為什麼（例如「D(3, 2) 取刪除：D(2, 2) ＋ 1.0 ＝ 1.1，比替換的 1.6 小」）。
- 放在 `aria-live="polite"` 區域，播放時螢幕閱讀器逐步念出；連續播放時只念停下來的那一步。
- 有對應的文件段落時，句尾附「為什麼？」連到 bcdp.md 的該節。

### 動態規劃表 `DpMatrix`（改）

- 表格角色改為 ARIA grid：`role="grid"`、格子 `role="gridcell"`、列頭欄頭 `role="rowheader"`／`columnheader`。
- 單一 tab stop（roving tabindex），方向鍵在格子間移動，Home／End 到列首尾，Enter／Space 選取。
- 選取的格：`ring-2 ring-inset ring-primary`（取代目前的 amber）。
- 其餘（最佳路徑、熱度、規則色、格角箭頭）不變。

### 詞圖搜尋 `DawgExplorer`（改）

- 每個走訪的節點一列：路徑前綴、這一列的最小值（下界）、上限、結果。
- 剪枝的節點寫出原因：「下界 1.2 ＞ 上限 0.8，整個子樹略過」，不用紅色。
- 接受的詞：`text-primary font-semibold`（取代 emerald）。
- 逐步播放：每一步走訪一個節點，焦點列 `ring-primary`。
- 手機（`< md`）改成縮排清單，不畫樹。

### BCDP 分頁

四個面板，由上而下依計算順序排列；每個面板標題旁有對應 bcdp.md 章節的連結。

1. **詞綴各層與交界狀態**（bcdp.md §4–5）：查詢的每個位置一欄；列是前綴第 1 … k 層、前綴合併（詞幹起點）、後綴第 1 … k 層、後綴合併（詞尾耦合）。每格是對齊走到「查詢位置 x、這個交界」的最小成本；後綴由詞尾往內算，這裡換回正向位置。表下註明還沒走完、會跨越交界的規則數（跨界表）。
2. **通道與詞圖走訪**（§6–7）：每個通道一列：通道的查詢字串、說明（沒有前綴、接在前綴之後、環綴 ta-…-aw、拿掉中綴 <x>、拿掉重疊部分、拿掉環綴的左邊；還原變體接在前綴之後時另外註明；併進了要求詞根元音開頭的環綴時，另外列出「元音開頭的詞根接 ma-…」），以及走訪的節點數與上限內的詞數。截斷時顯示「變體超過上限，已截斷」。
3. **整個詞的對齊**（§8）：詞素晶片依序排列、交界以「｜」分開（詞綴 `bg-muted`、詞根 `bg-accent`），下方是整個詞的對齊（沿用 `AlignmentStrip`），逐步播放時一步一步出現。
4. **分析**（§1）：步驟晶片依詞中的順序（前綴、重疊、詞根、中綴、後綴），每步成本；音變成本；合計「步驟 ＋ 音變 ＝ 總成本」。找不到時說明原因：就是查詢本身、詞根太短、超過總成本上限、超過截斷線。

另外：

- 輸入：查詢 q、詞根 t（可省略：省略時列出所有命中，點選其中一個）。
- 例子按鈕：站台設定 `lab.morph`（見第 8 節）；另有一組「找不到的例子」，說明為什麼找不到（例如需要規格中沒有描述的交界現象）。
- `lemmaSpread` 截斷：命中清單下方註明「只保留成本在最佳 ＋ 0.6 之內的詞；其他詞是否出現，取決於同一次查詢的最佳命中」。
- 沒有 `morphology` 的站台（例如 babizu 的 `examples/minimal`）不顯示這個分頁。

## 6. 步驟模型

每個分頁的播放都由一個與 Vue 無關的步驟產生器提供（`src/fuzzy/steps.js`）：

- 每一步是 `{ kind, phase, focus, note: { key, params }, proofRef? }`；`note.key` 是說明的中文原文（`steps.js` 的 `CELL_NOTES` 等表），經過 `t()` 顯示。
- 畫面狀態完全由步驟序號推出，所以跳到任何一步都是純函式；網址的 `step` 參數可以重現同一個畫面。
- BCDP 的步驟依序：前綴各層 → 後綴各層 → 合併 → 每個通道（變體）→ 每個通道的詞圖走訪 → 命中 → 整個詞的對齊（每一步）。
- 資料來自 `morphSearch.explain(query, term)`，它與搜尋走同一套程式，命中必須與 `finish` 的結果相同，對齊的成本加上步驟成本必須等於命中的成本（測試保證）。

## 7. 動畫與互動

**原則**：動畫只表達狀態變化。播放就是把步驟序號加一；畫面上變的只有新算出的格、焦點與說明。

- 過渡：格子的 `background-color` 與 `box-shadow`（焦點環）120 ms；其餘沒有動畫。
- 沒有入場動畫、捲動動畫、視差、數字跳動。
- 播放時焦點移到視窗外，只在「目前格完全不可見」時捲動（`scrollIntoView({ block: 'nearest' })`），不要每步都捲。
- **鍵盤**（焦點不在輸入框時）：
  - `←`／`→`：上一步、下一步
  - `Space`：播放、暫停
  - `R`：重來
  - `Home`／`End`：第一步、最後一步
- **網址**：`tab`、`a`／`b`（DP、詞圖）、`q`／`t`（BCDP）、`step`。改變時以 `router.replace` 更新，不留下每一步的瀏覽紀錄。

```css
@media (prefers-reduced-motion: reduce) {
  /* 不做過渡；播放仍可使用，但每一步直接換成新狀態，也不自動捲動 */
  .lab-cell { transition: none; }
}
```

## 8. 站台設定

`lab` 區段新增 `morph`（選填）：

```js
lab: {
  pairs: [['semer', 'semee']],
  morph: {
    examples: [['minudox', 'daux'], ['kiikita', 'kita'], ['binaket', 'baket'], ['bitudun', 'bitut']],
    failures: [['maxapux', 'apux']],
  },
}
```

- `examples`：[查詢, 詞根]；第一組是 BCDP 分頁的預設值。詞必須在站台的資料中。
- `failures`：找不到的例子，分頁會說明原因。
- 省略 `morph` 時：有 `morphology` 的站台以空白輸入開始，沒有的站台不顯示分頁。

## 9. 該做與不該做

### 該做

- 每個畫面只有一個焦點，焦點用主色的外框。
- 每一步都有一句話說明，數字寫出算式（`0.3 ＋ 0.1 ＝ 0.4`），不只寫結果。
- 剪枝、略過、找不到都寫出原因。
- 所有互動都能用鍵盤完成；表格是 ARIA grid，一個 tab stop。
- 新文字直接用中文寫在程式裡，英文譯文加進 `locales/en.json`。
- 用站台資料中的真實詞當例子。

### 不該做

- ❌ 在元件裡寫顏色值或 Tailwind 調色盤顏色；只用語意 token。
- ❌ 主色以外的強調色（amber 的選取框、emerald 的接受、紅色的剪枝）。
- ❌ 只用顏色區分操作類型；一定要有符號。
- ❌ 陰影、漸層、玻璃效果、發光。
- ❌ 入場動畫、數字跳動、自動輪播。
- ❌ 播放時每一步都捲動頁面。
- ❌ 為了動畫另建一份演算法；步驟必須來自正式實作的 `explain`，與搜尋結果一致。
- ❌ 在框架程式裡寫死任何語言、詞或變體代碼。
- ❌ 把設定欄的內容渲染兩份再用 CSS 隱藏其中一份。
