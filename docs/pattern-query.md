# 句型搜尋

句型搜尋讓讀者用接近正規表達式的寫法，依**詞序**與**構詞**找例句，例如：

| 查詢 | 找的是 |
|---|---|
| `yaku ka _* isiw` | yaku ka 與 isiw 中間隔任意幾個詞的句子 |
| `pa-… ki _` | 最外層的前綴是 pa- 的詞，後面接 ki 與一個詞 |
| `…-pa-…` | 前綴中有 pa- 的詞（不必在最外層） |
| `m<in>u-…` | 主事焦點完成貌的詞（m‹in›u-、m‹in›-、mi‹in›- 都算） |
| `ini _` | ini 後面接什麼（看「頻率」分頁） |

給語言研究者、教師與學習者用，所以：

- **寫法要能教**：沿用辭典與語法書的寫法（`ta-…-i`、`<in>`、`~`、語法書的 `iu/maki`），以及正規表達式的量詞。
- **結果要說得出理由**：每個命中的詞都標出怎麼符合（完全相符、相近拼寫、自動拆解、確定派生…），標籤與一般搜尋相同。
- **與一般搜尋、與 BCDP 一致**：每一種詞的條件都用一般搜尋同一個函式；構詞條件用 BCDP 的同一個分析，
  也就是一般搜尋「自動拆解」列出的拆法（第 4 節）。

程式在 `src/pattern/`（`babizu/pattern`），由 `SearchEngine.searchPattern` 執行；介面在 `app/src/components/pattern/`，寫法說明在「關於」頁（`PatternGuide.vue`）。

## 1. 寫法

一個查詢是一或多個**條件**，以 `&` 連接。每個條件描述一段**連續的詞**。

| 寫法 | 意思 |
|---|---|
| `kita` | 這個詞；依模糊程度容許方言與拼寫差異（與一般搜尋的「完全相符＋相近拼寫」相同） |
| `"kita"`、`"yaku ka"` | 拼寫完全相同；引號中有空白時是連續的幾個詞。`“”` 也可以 |
| `pa…`、`…an`、`…ki…`、`pa…an` | 只看拼寫：開頭、結尾、包含（`…` 是零個以上的字元；也可以打 `...`） |
| `pa-…`、`…-en`、`ta-…-i`、`<in>…`、`~…`、`pa-kita`、`…-pa-…` | 構詞樣式（第 3 節） |
| `@kita` | 詞族：kita 本身、相近拼寫、確定派生（辭典標註）、自動派生 |
| `_` | 任一個詞 |
| `x?` `x*` `x+` `x{n}` `x{n,m}` `x{n,}` | 量詞：可有可無、零個以上、一個以上、次數（最多 30）。**要緊接在詞後面** |
| `(a b)` | 分組 |
| `(a\|b)`、`a/b` | 擇一（`/` 是一格內的簡寫，同語法書的 `iu/maki`） |
| `^`、`$` | 句首、句尾 |
| `!x`（在序列中） | 一個「不是 x」的詞；x 必須正好佔一個詞（`!ki`、`!(ki\|ni)`） |
| `A & B` | 同一筆記錄中 A 與 B 都要有，順序不拘 |
| `A & !B` | 有 A，而且沒有 B（`&` 後面的 `!` 否定整個條件） |

### 1.1 文法（EBNF）

運算的結合由緊到鬆：`/` → 前置 `!` → 量詞 → 相鄰 → `|` → `&`。

```
query   = cond { "&" [ "!" ] cond } ;
cond    = alt ;
alt     = seq { "|" seq } ;
seq     = item { item } ;
item    = unary [ quant ] ;               (* 量詞與前面之間不能有空白 *)
unary   = "!" unary | primary ;
primary = "(" alt ")" | "^" | "$" | slot ;
slot    = chunk { "/" chunk } ;
quant   = "?" | "*" | "+" | "{" n "}" | "{" n "," "}" | "{" n "," m "}" ;
chunk   = "_" | 詞 | "詞" | 拼寫樣式 | "@" 詞 | 構詞樣式 ;
```

- 第一個條件一定是正面的，它開頭的 `!` 是序列中的 `!`：`!ki _` 是「一個不是 ki 的詞，接著任一個詞」。
  要在 `&` 後面的條件開頭用序列中的 `!`，加括號：`yaku & (!ki) _`。
- 條件不能什麼詞都不比對（`_*`、`kita?` 單獨成一個條件是錯誤）；加量詞的部分也不能（`(_?)*`）。
- 詞中的標點（`, . ; :`）忽略並提示（從語料複製句子時常帶著）。
- 上限：查詢 256 個字元、32 個詞的條件。

## 2. 比對的語意

### 2.1 與正規表達式相同

把每個詞當成一個字元、每個詞的條件當成一個字元類別，句型就是一個正規表達式：
`_` 是 `.`、`!x` 是 `[^x]`、相鄰是相接、`|` 是擇一、量詞是貪婪的重複、`^ $` 是頭尾。
找到的區間與 JavaScript RegExp 的 `g` 旗標完全相同：

1. **最左**：從最前面的起點試起；
2. **優先序**：同一個起點有好幾種比法時，取回溯法最先試到的。擇一依寫的順序，量詞先試多的（貪婪）；
3. **不重疊**：下一次從上一次的終點接著找。

所以 `yaku ka _* isiw` 在「yaku ka mausay mikita isiw a mamai … ezaw isiw」中比到最後一個 isiw。
單元測試以兩萬組隨機句型對照 RegExp 檢查這一點（`test/pattern/match.test.js`）。

### 2.2 句、讀法

- **切詞**與搜尋索引相同（空白與標點；搜尋鍵刪除體例符號，`talubik-ay` → talubikay）。
- **分句**：詞後面有句末標點（`. ? !` 與全形）時另起一句。相鄰、`^`、`$` 以句為單位，`_*` 不會跨到下一句。
- **語法書的體例**（林鴻瑞《噶哈巫語參考語法》的例句）：

  | 寫法 | 處理 |
  |---|---|
  | `(ka)` | 可以省略：有與沒有各是一種讀法 |
  | `iu/maki` | 同一個位置擇一 |
  | `iu/*maki` | `*` 的選項不合語法，不參與 |
  | `*(ki)` | 不能省略，照常 |
  | `ma(a)sik` | 詞中括號裡的字母可有可無 |

  一筆記錄的每一種組合是一種**讀法**，最多 16 種，超過時只用第一種：可省略的都保留、擇一取第一個。
- **條件與讀法**：
  - 正面的條件在任一句、任一種讀法比到就算；
  - `& !` 的條件在任何一種讀法比到，整筆就排除；
  - 同一個區間由不同讀法比到時只算一次。

### 2.3 適用的記錄

所有記錄都適用（詞綴與詞的條目、片語、句子；詞就是只有一個詞的序列），可以用篩選面板的來源、方言、語言單位篩選。
結果依語言單位分成三區（`search.js` 的 `PATTERN_GROUPS`）：**詞條**（`affix`、`word`）、**片語**、**句子**。
各區各自排序、各自取前 `limit` 筆，例句再多也不會把詞條擠出回傳的範圍；介面每區一個標題，也可以只看一區。
模糊程度影響不加引號的詞、構詞樣式寫出的詞根與 `@`。搜尋範圍與搜尋方法的篩選不適用：句型只比對族語，詞的條件由寫法決定。

### 2.4 分數與排序

每個命中的詞有一個分數，與一般搜尋同一套規則（`scoring.js` 的 `rankScore`、`recordScore`）：

| 怎麼比到 | 分數 |
|---|---|
| 完全相符、`_`、`!x` | 0 |
| 相近拼寫 | 距離 |
| 開頭、結尾、包含 | 0.35 或 0.9 起 |
| 構詞（自動拆解、自動派生） | 0.4 ＋ 成本 |
| 確定派生 | 加上層數 × 0.1 |

區間的分數是各詞相加，一筆記錄的分數是每個正面條件最好的區間相加。每一區內依分數排序，同分依記錄的順序。

## 3. 構詞樣式

構詞樣式在剖析時解析成一組**詞素條件**，與 BCDP 分析中的詞素比對。比的是詞素，不是字串。
BCDP 的分析保留每個詞素實際用的寫法（構詞文法展開後的 `parts`），例如：

- minukan ＝ AF:mu ＋ PRF:in
- mineken ＝ AF:m ＋ PRF:in
- pinakita ＝ CAUS:pa ＋ PRF:in

### 3.1 分段

- 以 `-`、`=`、`~` 分段，`=` 與 `-` 相同（不區分詞綴與附著詞）。
- `…` 是詞根段。沒有 `…` 時，詞根段是「其他段都解析得成詞綴」的那一段（`pa-kita` 的 kita）。
  好幾段都可以時（`tau-en`：tau 加 -en，或是前綴 tau- 加 en），只留 BCDP 可能當成詞根的：至少 `minStem` 個字元，
  而且是詞庫中的詞或虛擬詞根。還是不只一段（或一段都沒有）時報錯 `E_AMBIGUOUS_ROOT`。
- 頭尾的空段是省略的 `…`：`pa-` ＝ `pa-…`、`-en` ＝ `…-en`、`-pa-` ＝ `…-pa-…`。
- **外側的 `…`**：寫在第一段或最後一段、與詞根之間隔著詞綴的 `…`，表示那一側不錨定（3.4 節）：
  `…-pa-…`、`…-ka-…-en`、`…-pa-kita`、`…-ta-…-i-…`。
  哪一個 `…` 是詞根由中間的詞綴決定（`morph.js` 的 `resolve`）：逐一假設每一段是詞根，
  其他段都要解析得成那一側的詞綴、外側的 `…` 只能在頭尾而且與詞根之間要有詞綴。
  **`…` 優先當詞根**：有 `…` 當得成詞根的讀法時只看這些（`saa-i-…` 是前綴 saa-、i-，不是詞根 saa 加後綴 -i 再加外側的 `…`）；
  `…` 都當不成詞根時才考慮寫出的詞根（`kita-en-…`、`…-pa-kita`）。只有一種讀法成立時就是它。
  `…-i-…` 的 i 是前綴也是後綴，兩種讀法都成立，報錯 `E_AMBIGUOUS_SIDE`，建議只看最外層的 `i-…` 或 `…-i`。
- 兩個 `…` 相鄰（`…-…`）、不在頭尾的 `…` 有兩個以上（`pa-…-ka-…-en`）報錯 `E_MULTI_ROOT`。
  `…` 不能和字母連在同一段（`m<in>…` 要寫 `m<in>-…`）。
- `x~` 是重疊。重疊部分由詞根決定，x 寫不寫都一樣；`~…` 是「有重疊」。

### 3.2 中綴不看位置

中綴插在整個詞的第一個輔音（群）之後，位置由語言決定，查詢的人不必知道它落在哪裡。

- `<x>` 寫在樣式的任何地方，都只表示「這個詞含中綴 x」。
- 中綴旁邊的字母屬於它的宿主：`m<in>u-` 的宿主是前綴 mu，`b<in>aket` 的宿主是詞根 baket。
- `m-<in>`、`<in>-` 的中綴獨立成段。

所以 `m<in>u-…`、`m<in>-…`、`m-<in>…`、`m-<in>-…` 都是「主事前綴＋中綴 in」，結果相同。

### 3.3 詞綴寫法的解析（`morph.js` 的 `resolveAffix`）

依序：

1. **同位詞素組**：構詞文法中寫在同一個詞素 `forms` 的寫法，再把共用寫法的同一類詞素（同為前綴、中綴或後綴）連成一組。
   巴宰語的 AF {m, mu, mi, me}、AF.m {m}、AF.C {mu, mi, me} 是同一組，所以 `m-…`、`mu-…`、`mi-…`、`me-…` 等價。
   寫在引號中（`"mu"-…`）只要那個寫法，讓研究者可以看同位詞素的分布。
2. **組合的整體寫法**：構詞文法展開出的組合換成它的詞素，例如 `mina-…` ＝ `ma-<in>…`、`minu-…` ＝ `mu-<in>…`。
   同一個寫法也是某個組合的整體寫法時，附上提示：`ma-` 是狀態 ma-，進行貌的 m‹a›- 表面也寫成 ma。
3. **方言寫法**：以上都不是時，用語言設定檔的距離函式找最近的詞綴（距離 ≤ 0.25）。
   例如噶哈巫語的 `mo-` 依 u↔o 視為 mu-，附提示；這與 BCDP 對詞綴音變的處理相同。
4. **找不到就報錯**，列出最接近的三個。BCDP 只認得規格中的詞綴，不認得的寫法永遠比不到，所以直接報錯，不回傳空結果。

| 寫法 | 解析成 |
|---|---|
| `mu-…`、`mi-…`、`m-…`、`me-…` | 主事組 {m, mu, mi, me} |
| `m<in>u-…`、`m<in>-…`、`m-<in>…`、`minu-…` | 主事組 ＋ 中綴 in |
| `<in>…` | 任何含中綴 in 的詞 |
| `b<in>aket`、`<in>baket`、`<in>-baket` | 詞根 baket ＋ 中綴 in |
| `mina-…` | ma ＋ 中綴 in |
| `"mu"-…` | 只要寫成 mu 的 |
| `…='en`、`…-en`、`…-un` | 受事組 {en, un} |
| `mo-…` | 視為 mu-（提示） |
| `…-mu-…` | 前綴中有主事組（不必在最外層） |
| `b-…` | 錯誤：b 不是詞綴（最接近的：pa-、pi-、pu-） |

這張表的每一列都有單元測試（`test/pattern/search.test.js`，用合成的構詞文法）。

### 3.4 比對規則（`morph.js` 的 `satisfies`）

- **前綴從最外層算起**：樣式中的前綴（由外而內）必須正好是這個拆法**最外面的幾個前綴**，而且彼此相連。
  `pa-ka-…` 找得到 pa-ka-x、pa-ka-ma-x，找不到 ka-pa-x、pa-ma-ka-x、ma-pa-ka-x。
- **後綴同樣從最外層算起**：`…-an-ay` 找得到 x-an-ay、x-i-an-ay，找不到 x-an-ay-i。
- **列出的詞綴與詞根之間**可以有沒列出的詞素，由 `…` 或寫出的詞根吸收：`pa-…` 與 `pa-kita` 都找到 pa-ka-kita。
- **外側寫了 `…` 的那一側不錨定**：列出的詞綴在那一側的任何位置連續出現即可。
  imini 拆成 i-mini 或 i-m-ini，最外層的前綴是 i-，所以 `m-…` 不中，`…-m-…` 中。
- **中綴、重疊**：不看位置，只要有。同一個中綴寫兩次要有兩個。
- **詞根**：寫出詞根時，拆法的詞根要在依模糊程度的拼寫集合中（第 4 節）。

為什麼從最外層算起：v0.6.0 讓詞綴在任何位置都算，雜訊太多（imini 沿 ini → mini → imini 也算 `mu-…`）。
讀者寫 `pa-…` 想的是「pa- 開頭的衍生詞」，要找夾在裡面的寫 `…-pa-…`；
錨定的樣式能多找到詞時，結果上方提示改寫後多幾個詞形（`W_INNER_AFFIX`，可以點）。

### 3.5 詞素從哪裡來：拆解表

每個詞的拆法來自**拆解表**（`src/search/parses.js`，建置輸出 `search/parses.json`）：
詞庫中每個詞的所有 BCDP 拆法，也就是一般搜尋查這個詞時「自動拆解」列出的那一串。

- 每個候選詞根取最好的那一種分析，範圍在「最好的 ＋ lemmaSpread」之內、總成本 ≤ 1；
- 詞根比這個詞短、是單一個詞（不含空白；BCDP 可以把片語當詞根，例如把 pakakita 拆成 pa- ＋「ka kita」）；
- 加上自動派生圖中這個詞的虛擬詞根（詞庫外的共同詞根，`bcdp.md` 第 10 節）；
- BCDP 最好的命中不是拆法時（詞根不比詞短或含空白），另外記下它的成本（`best`）。
  例如 abak 最好的命中是 a- ＋ barak（0.25，詞根比詞長），唯一的拆法是 a-pa-rak（0.55）。

**詞庫外的詞**：語料中的詞幾乎都在詞庫中，例外是例句體例展開的讀法（`ma(ki)kiahan` 的 makiahan、makikiahan；
巴宰–噶哈巫語資料 22 個），建置時沒有算。查詢時用建置拆解表的**同一個函式**現算（`derivations.js` 的 `analyzeWord` 與
`virtualRoots`，條件相同；`PatternSearch._unlistedParses`），結果與把它加進詞庫建置時拆解表的內容相同（單元測試逐一比對）。
不加引號的詞也查這些讀法：用同一個距離函式與同樣的門檻，在它們組成的小詞圖上比對（`PatternSearch.unlistedIndex`）。

一種拆法的詞素是它各步驟的詞素合起來（`readingOfSteps`）：前綴由外而內，後綴由內而外。
例如 pausunguday 的一種拆法是 p‹a›u-sungut-ay（一個組合規則），所以 `pu-…`、`<a>…`、`…-ay`、`pu-<a>…-ay` 都找得到它。

**只拆一層**，不沿詞根再往下拆：BCDP 一次分析就能剝掉好幾個詞綴（`maxSteps`），多層的詞多半直接拆得到。
研究紀錄 U.19 的探索性量測（同樣 184 個詞，條件沒有合併同位詞素組，所以數字與 3.6 節不能直接比）中，再往下疊時召回 92.0% → 93.1%、準確 73.9% → 72.1%，多出來的大多是巧合
（siisinaw → ‹in›saw、bibinayu → ‹in›bayu）。

### 3.6 依模糊程度取拆法（`morph.js` 的 `PARSE_SELECTION`）

拆法有兩種，**分開取，不放在同一個尺度上比**，與自動派生圖的兩種邊相同：

- **詞庫詞根的拆法**（BCDP）：先求 best＝BCDP 在詞庫中最好的命中（`ParseChart.lexicalBestOf`；最好的命中不是拆法時是那個命中），
  取成本在 best ＋ spread 之內的，再去掉音變（整個詞的方言音變，成本扣掉各步驟的成本；構詞音變算在步驟裡）超過上限的。
- **虛擬詞根的拆法**：自動派生圖已經只留成本最低的，全部取（沒有音變）。它們只補充，**不把詞庫詞根的拆法擠掉**：
  虛擬詞根的成本是精確列舉的步驟成本，剝掉的詞綴少就便宜，與 BCDP 的成本不能比。

| 模糊程度 | spread | 音變上限 | 準確 | 召回 |
|---|---|---|---|---|
| 精確 | 0（同分都取） | 0.2 | 75.4% | 85.2% |
| 標準 | 0.1 | 0.2 | 68.1% | 88.6% |
| 寬鬆 | 全部 | 0.4 | 57.5% | 91.5% |
| v0.6.0（三種模糊程度幾乎相同；這是標準） | | | 59.9% | 87.5% |

所以精確模式取到的，就是自動派生圖這個詞的邊（詞庫詞根同分全收、虛擬詞根）去掉音變超過 0.2 的；
精確與標準的差別只在要不要取次佳的拆法。

- 準確與召回以潘德興詞彙表 184 個人工拆解（`morphology.segmentation`）為標準（minubizu `tools/eval-parse-gold.mjs`）：
  標準答案中出現的每個最外層前綴、最外層後綴與中綴寫成 `x-…`、`…-x`、`<x>…`，同一個詞素組只算一次（15 組），
  看整個句型搜尋的結果有沒有這個詞。標準比 v0.6.0 更保守（準確 ＋8.2），也找得更多（召回 ＋1.1）。
- **兩個曾經的錯誤**（研究紀錄 U.20，各有不變式測試守著）：
  - 虛擬詞根與詞庫拆法放在一起求 best：pinahazaban 的 pa-‹in›hazap-an（0.25，交界濁化 0.05）被虛擬詞根
    pinahazab-an（0.1）擠掉，`pina-…-an`、`pa-<in>…-an` 找不到它；語料中 344 個詞受影響。
  - 精確模式不容許任何音變：交界濁化這種規律的構詞音變也被擋掉，最好的拆法落選；準確與召回都比較差（72.6%、60.2%）。
- 剩下的誤配有一部分是標準答案與構詞規格的寫法不同：詞彙表寫 pa-ka-X，規格中 paka- 是一個詞素；
  詞彙表把進行貌寫成前綴 a-（m-a-idem），規格是中綴 ‹a›。新舊版本都受同樣的影響。
- **best 包含 BCDP 最好的命中**，與自動派生圖不建邊的條件相同：abak 最接近的是 a- ＋ barak，
  巧合的 a-pa-rak 差太多，標準模式不收。
- **先求 best 再扣音變**是刻意的：最好的拆法音變太多時，比它差的拆法多半是巧合，精確模式不改取它。
- 比到的不是這個詞最好的拆法時，證據附上最好的成本（`analysis.bestCost`），介面在「自動拆解」標籤上標「次佳」並說明。
- 精確模式下一般搜尋不做構詞比對；構詞樣式是明確寫出的條件，照樣比對，附提示 `W_EXACT_MORPHOLOGY`。

## 4. 與 BCDP 的對稱

構詞條件不另寫一套分析：唯一的來源是**拆解表**（3.5 節），它與自動派生圖來自建置時**同一次 BCDP**
（`derivations.js` 的 `analyzeAll`）：自動派生圖只取每個詞最好的詞根，拆解表全收。所以：

- 拆解表中與 BCDP 最好的命中同分的詞庫詞根，就是自動派生圖這個詞的邊（`ParseChart.lexicalBestOf`）；虛擬詞根的邊兩邊相同。
  精確模式取到的拆法，就是自動派生圖的邊去掉音變超過 0.2 的那些（不變式測試；真實資料 `tools/eval-pattern.mjs` 1c）。
- 虛擬詞根不把詞庫詞根的拆法擠掉：每個詞、每種模糊程度，取到的詞庫拆法與沒有虛擬詞根時相同（不變式測試；1d）。
- **每個詞都找得到自己**：依模糊程度取到的每一種拆法寫成構詞樣式（詞根寫 `…` 或引號中的詞根），結果一定有這個詞、也不報錯
  （合成資料的單元測試；真實資料 `tools/eval-pattern.mjs` 第 4 項，三種模糊程度約 7 萬個樣式）。
  這一項把剖析、詞綴解析、取拆法、比對一起檢查，曾經找出 `saa-i-…` 報錯（… 優先當詞根，3.1 節）。
- 拆解表中的詞庫詞根與成本，就是一般搜尋查這個詞時自動拆解列出的那些（詞根比詞短、單一個詞）。

**詞根是 `…` 與寫出詞根用同一個條件**：一個詞符合 `P(r)`，若且唯若它取到的某個拆法符合 P 的詞綴條件、而且詞根在 r 的詞根集合中；
`P(…)` 只是不看詞根。由此直接得到：

> 對任何構詞樣式 P 與任何模糊程度，`P(…)` 找到的詞，等於每一個詞根 r 的 `P("r")` 找到的詞合起來。

- **詞根集合**：寫在引號中時只有它本身；否則是它與依模糊程度的相近拼寫，與一般搜尋自動派生的起點相同（`SearchEngine.derivationSeeds`）。
- **測試**：
  - 合成資料：`test/pattern/search.test.js`「拆解表」逐一檢查每個詞的拆解表對自動派生圖、對一般搜尋的自動拆解，
    以及六種樣式在三種模糊程度下的對稱；
  - 真實資料：minubizu 的 `tools/eval-pattern.mjs`；
  - 動物園：拆解表漏掉虛擬詞根、只收最好的詞根、收下含空白的詞根，都會被殺掉。

**與一般搜尋一致**（同一個函式，`test/pattern/search.test.js`「與一般搜尋一致」）：

| 句型 | 等於一般搜尋的 |
|---|---|
| `kita` | 完全相符＋相近拼寫（`_fuzzyTerms`） |
| `@kita` | 完全相符、相近拼寫、自動派生、確定派生（`_matchTerms`、`_dictionaryTokens`；其他方法排除時的結果） |
| `pa…` | 「開頭相符」的意思，但 `…` 可以是零個字元，所以 pa 本身也算 |

**刻意的差別**：詞中有括號的記錄（例句體例 `pa(ka)kita`）。一般搜尋在括號處斷開成 pa、ka、kita，查 kita 會找到它；
句型搜尋依體例讀成 pakakita 與 pakita（2.2 節），`"kita"` 找不到、`"pakakita"` 找得到。
這種讀法大多不在詞庫中（巴宰–噶哈巫語資料 22 個），它們的拆法在查詢時用建置拆解表的同一個函式現算（3.5 節），
所以構詞樣式照樣比得到（`yaku pa-ka-…` 找到 `yaku pa(ka)kita isiw`）。

證據的形狀與一般搜尋例句的 `OccurrenceMatch` 相同，介面直接用 `HitTags` 顯示。
構詞樣式一律是「自動拆解」（這個詞 → 詞根），音變說明只為前幾筆結果計算（與建置自動派生圖時同一個計算）。

## 5. 自動判斷與模式

網站只有一個搜尋框。查詢用到**句型專用的寫法**時改用句型搜尋（`detect.js` 的 `looksLikePattern`，介面與 Web Worker 共用）：

- 單獨的 `_`
- `…`、`...`
- 引號
- `|`、`&`
- 開頭的 `^`、結尾的 `$`
- 前置的 `!`（後面緊接一個詞或括號）
- `{n,m}`
- `)` 後接量詞
- `@詞`

量詞 `? * +`、連字號、`=`、括號單獨出現時都**不算**，因為讀者常照辭典或語法書的寫法輸入：
`pa-kita`、`sikis-`、`ha=ka`、`kita?`、`yaku (ka) mupuza lia.`、`bunang ka lalan!` 都照舊走一般搜尋（回歸測試 `test/pattern/parser.test.js`）。

網址參數 `m`：

| 值 | 模式 |
|---|---|
| `m=plain` | 強制一般搜尋 |
| `m=pattern` | 強制句型搜尋 |
| 未指定 | 自動判斷 |

換了查詢就回到自動判斷。句型模式的結果上方有「以句型搜尋 · 改用一般搜尋 · 句型的寫法」；被強制以一般搜尋時，提示可以切回句型搜尋。

## 6. 錯誤與提示

剖析與解析的錯誤丟出 `PatternError`（代碼、在查詢中的範圍、參數），搜尋回應的 `error` 帶著它，不丟出例外。
引擎在 Web Worker 中不能翻譯，代碼的說明文字在介面（`app/src/lib/pattern.js`），依介面語系顯示。代碼一覽見 `src/pattern/errors.js`。

| 代碼 | 情形 |
|---|---|
| `E_UNCLOSED_PAREN`、`E_UNCLOSED_QUOTE`、`E_UNCLOSED_INFIX` | 括號、引號、中綴沒有結束 |
| `E_EXPECTED_ITEM`、`E_UNEXPECTED` | 缺了詞、多了符號 |
| `E_QUANT_POS`、`E_QUANT_RANGE`、`E_BAD_QUANT` | 量詞的位置、次數 |

| `E_NEG_WIDTH` | `!` 後面不是正好一個詞 |
| `E_UNKNOWN_AFFIX` | 不認得的詞綴，附最接近的幾個 |
| `E_MULTI_ROOT`、`E_AMBIGUOUS_ROOT`、`E_WILDCARD_ATTACHED`、`E_EMPTY_SEGMENT`、`E_QUOTE_POS` | 構詞樣式的分段 |

| `E_NO_MORPHOLOGY` | 語言設定檔沒有構詞規格，卻用了構詞樣式 |

| `W_TRAILING_Q` | 最後的 `?` 是可有可無，不是問號 |
| `W_PUNCT` | 詞中的標點已忽略 |
| `W_EXACT_MORPHOLOGY` | 精確模式下構詞樣式只取最好的拆法、不容許音變 |
| `W_INNER_AFFIX` | 列出的詞綴只算最外層；改寫成 `…-x-…` 多找到幾個詞形（`params.query` 是改寫後的整個查詢，介面做成連結） |

## 7. 回應（`PatternResponse`）

```
{ query, mode: 'pattern', error: PatternIssue | null, warnings: PatternIssue[],
  hits: [{ doc, score, group, matches: [{ cond, start, end, score, cells: [{ start, end, key, slot, evidence }], left, right }] }],
  groups: [{ key: 'entries' | 'phrases' | 'sentences', total }],
  slots: [{ label, start, end, anchor }],
  frequency: [{ slot, total, distinct, rows: [{ form, count, docs }] }],
  totals: { hits, matches }, stats: { elapsedMs, candidates, truncated } }
```

| 欄位 | 內容 |
|---|---|
| `start`、`end` | 在原文中的位置（UTF-16），介面直接依位置高亮，不重新切詞 |
| `group`、`groups` | 這筆記錄屬於哪一區（詞條、片語、句子）；每區的記錄數。`hits` 依分區排列，每區最多 `limit` 筆 |
| `evidence` | 這個詞怎麼符合（`_` 與 `!x` 為 null） |
| `slot` | 屬於主條件（第一個條件）的第幾格（頂層的第幾項） |
| `left`、`right` | 區間左右各三個詞（由近到遠），語詞索引排序用 |
| `frequency` | 主條件每一格（`^ $` 除外）的詞形次數，以全部命中計算；每格最多列 100 種 |

## 8. 實作

| 檔案 | 責任 |
|---|---|
| `lexer.js` | 切成詞塊與運算符號；引號中的文字與緊鄰的文字合成一個詞塊（`"mu"-…`） |
| `parser.js`、`ast.js` | 遞迴下降剖析；語法樹與它的性質（`widthOf`：佔幾個詞；`requiredAtoms`：必經的詞） |
| `detect.js` | 自動判斷 |
| `match.js` | 比對器（下面說明） |
| `sentences.js` | 切詞、分句、讀法、原文位置 |
| `morph.js` | 構詞樣式的解析、詞素、比對、依模糊程度取拆法 |
| `search.js` | `PatternSearch`：每個詞的條件求成「詞形 → 證據」，篩選候選，逐筆比對，排序、頻率 |

**比對器**不用虛擬機器，直接依語法樹遞迴求值：

- `ends(節點, 起點)` 回傳這個節點從起點能比到的所有終點，**依優先序排列**、同一個終點只留第一次出現。
  - 相接：依序取前一項的每個終點，再接下一項；
  - 擇一：各分支的終點依分支順序串起來；
  - 重複：先試再多比一次，最後才是停在這裡。
- 同一個終點只留第一次出現是安全的：後面的節點只看位置，不看是怎麼比到的。
- 以（節點、起點、重複次數）記憶，一句最多約 25 個詞，成本是 O(節點數 × 詞數²)。
- 區間定下來之後，`walk` 依同樣的優先序還原每個詞由哪一個條件比到。

**候選篩選**：每個正面條件必經的詞的條件（不在可省略的部分、擇一的分支或 `!` 裡），都要有詞出現在記錄中，記錄才可能比對成功。
先用它們取交集，再逐筆比對；這只是加速，關掉時結果相同（單元測試對照）。

**快取**：

- 第一次句型查詢時把所有記錄切成句與讀法（約 15,000 筆，一百多毫秒）；
- 拆解表（約 1 MB）網站在第一次遇到構詞樣式時才載入（`SearchEngine.needsParseChart`、`attachParseChart`），
  每個詞的拆法第一次用到時解碼，依模糊程度取到的拆法與詞素依詞快取；
- 每個詞的條件依（條件、模糊程度）求一次。

**上限**：命中區間 10,000 個、每次 2 秒；超過時停止並標記 `truncated`，結果上方說明。

## 10. 已知限制

- 拆法是演算法推定的，結果一律標「自動」。剩下的誤配大多是 BCDP 本身難以分辨的：
  - m-／ma- 加上元音合併：maanu 可以是 m-aanu 或 ma-anu，maaisiay 也是；
  - 詞彙化的派生：kinadaxilan 最好的拆法是 kinadaxil-an（kinadaxil 本身是詞），要到寬鬆才有 ka-‹in›dahil-an，
    所以標準模式的 `<in>…` 找不到它。
- `i` 同時是前綴與後綴，`…-i-…` 有歧義（3.1 節），只能寫只看最外層的 `i-…` 或 `…-i`。
- `_*` 是貪婪的，延伸到同一句中最後一個接得上的地方；之後可以考慮非貪婪的 `*?`。
- 例句幾乎沒有逐詞註解。語法標記（`NEG`、`NOM`、`PFV`…）與依註解的條件留待以後（需要語言設定檔的詞類表）。
- 詞中括號的寫法（`ma(a)sik`）展開後的讀法大多不在詞庫中：構詞樣式與不加引號的詞照樣比得到（3.5 節），
  但 `@詞` 是一般搜尋的詞族，只含詞庫中的詞，比不到這些讀法。
- 兩段都是詞根、也都是對側的詞綴時（3.1 節），沒有寫法可以指定哪一段是詞根，只能改寫成 `…` 的樣式再看結果。
