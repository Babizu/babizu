# 語言設定檔

語言設定檔描述「搜尋時怎麼看待這個語言的拼寫」：哪些字元視為相同、哪些符號忽略、方言之間有哪些系統性的語音對應，以及（選填）這個語言的詞綴與構詞。
它是純資料（JSON），建置端用它建索引，網站的 Web Worker 用它處理查詢。兩邊讀同一份檔案，搜尋鍵才會一致。

這份文件前半說明每個欄位，後半（[編寫指南](#編寫指南)）說明怎麼為一個新的語言寫出方言規則與構詞規格、怎麼檢查、常見的錯誤。

## 完整範例

```json
{
  "format": "babizu-language-profile",
  "version": 1,
  "name": { "zh-TW": "示範語", "en": "Demo language" },
  "normalizer": {
    "lowercase": true,
    "charMap": { "ʔ": "'" },
    "stripDiacritics": true,
    "preserve": ["é"]
  },
  "notationChars": "-=<>…~*",
  "boundaries": [" "],
  "costs": {
    "substitute": 1.5,
    "delete": 1,
    "insert": 0.8,
    "overrides": { " ": { "substitute": 0.1, "delete": 0.1, "insert": 0.1 } }
  },
  "rules": [
    { "category": "流音", "label": { "en": "Liquids" }, "rules": [["r", "l", 0.1]] },
    {
      "category": "詞尾",
      "label": { "en": "Word-final" },
      "position": "final",
      "rules": [
        ["n", "ng", 0.1],
        ["h", "", 0.1]
      ]
    }
  ],
  "morphology": {
    "prefixes": [{ "form": "mu", "gloss": { "zh-TW": "主事焦點", "en": "AF" } }],
    "suffixes": [{ "form": "an" }],
    "infixes": [{ "form": "in" }],
    "reduplication": [{ "pattern": "Ca" }],
    "alternations": [{ "underlying": "t", "surface": "d", "position": "final", "cost": 0.05 }]
  }
}
```

## 欄位

### `normalizer` 正規化

比對之前，查詢與詞庫都經過同一套正規化，依序：

1. Unicode NFC
2. `lowercase`（預設 true）：轉小寫
3. `charMap`：逐字元對應。**疊加在框架預設對應之上**（各種撇號 `’ ‘ ʼ ´` → `'`、`ǝ` → `ə`、全形與不斷行空白 → 空白）；
   設 `"useDefaultCharMap": false` 可以不要預設對應。值可以是多個字元（`"ŋ": "ng"`）或空字串（刪除）
4. `stripDiacritics`（預設 false）：去除附加符號；`preserve` 列出的字元例外（例如噶哈巫語的 `é` 是獨立的音位）
5. 連續空白壓成一個、去除頭尾空白

`charMap` 不要寫成連鎖（`a → b` 又 `b → c`）：正規化必須**冪等**，已正規化的詞再正規化一次不能改變。建置端與搜尋端、搜尋引擎與詞庫索引可能對同一個詞各正規化一次，不冪等時兩邊的寫法會對不上。對應是依序套用的，連鎖的結果取決於先後順序，很容易寫錯（單元測試 `normalize.test.js` 有反例）。構詞搜尋只在正規化後的查詢上以字元切片，不再對片段正規化。

### `notationChars` 體例符號

辭典體例用的符號（詞綴連字號、附著詞等號、中綴括號…），建立搜尋鍵時刪除，但顯示時保留原樣。
預設 `-=<>…~*`。所以 `sikis-`、`ha=ka`、`<in>` 分別可以用 `sikis`、`haka`、`in` 找到。

### `boundaries` 詞邊界

決定規則的「詞首」「詞尾」範圍，預設 `[" "]`。片語中空白前後也算詞尾／詞首，所以 `bintul a ≈ bintun a`。

### `costs` 基本編輯成本

| 欄位         | 預設 | 說明                                                                               |
| ------------ | ---- | ---------------------------------------------------------------------------------- |
| `substitute` | 1.5  | 替換一個字元（相同字元為 0）                                                       |
| `delete`     | 1.0  | 刪除查詢的字元（查詢多打了）                                                       |
| `insert`     | 0.8  | 補上候選的字元（查詢少打了）                                                       |
| `overrides`  | —    | 針對單一字元覆寫，例如讓空白的三種操作都只算 0.1，`baruzakbinayu ≈ baruzak binayu` |

插入比刪除便宜，是因為使用者常只記得詞的一部分。所以距離不對稱：`distance(a, b)` 與 `distance(b, a)` 可能不同。

### `rules` 語音對應規則

依分類分組的規則表。每組：

| 欄位          | 說明                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------- |
| `category`    | 分類代號，也是預設顯示名稱。演算法實驗室可以整類開關                                         |
| `label`       | 各介面語系的分類名稱，例如 `{ "en": "Word-final" }`；只影響顯示                              |
| `description` | 說明（選填）                                                                                 |
| `position`    | 整組的位置限制：`any`（預設）、`initial`（詞首）、`final`（詞尾）                            |
| `rules`       | 規則列：`[來源, 目標, 權重]`，或物件 `{ source, target, weight, position?, bidirectional? }` |

規則的語意：

- **多字元對多字元**：`["aru", "aw", 0.1]`
- **一側可以是空字串**：`["r", "", 0.1]` 表示 r 脫落；兩側不能都空
- **預設雙向**：`r → l` 同時註冊 `l → r`；物件列可以設 `"bidirectional": false`
- **位置限制**對兩側都成立：`final` 表示來源片段在查詢的詞尾，**且**目標片段在候選的詞尾。構詞搜尋中，目標片段在詞素交界時（例如詞幹接後綴之前），查詢那一側不另外檢查（[bcdp.md](bcdp.md) 1.3）
- 權重必須非負（剪枝的正確性依賴這一點）；同一條規則重複出現時取最小權重
- 規則字串也會經過同一套正規化

### `morphology` 構詞（選填）

宣告這個語言的詞綴，搜尋就能雙向處理衍生詞：

- **詞根相符**（去詞綴）：查衍生詞，找到詞根，也列出辭典已標註的派生詞。詞幹與詞綴本身都可以帶方言音變：`minudox` 得到 `daux-`（`minu-` ＋ `dox`，dox → daux 是 o → au）。
- 音變以**整個詞**計算：同一套方言規則套在「詞綴 · 詞根 · 詞綴」接起來的字串上，可以跨越詞素交界。`takitaw`（ta- ＋ kita ＋ -aw）的 a｜a 由規則 aa → a 處理，`tau'alawan`（tau- ＋ alaw ＋ -an）交界上的喉塞音由詞首規則 ' → ∅ 處理，都不必在詞綴清單中另列異體。
- **衍生形**（還原詞綴）：查詞根，找到詞庫與例句中由它衍生的詞，包括中綴、重疊形式與方言變體。例如查 `baket` 得到 `binaket`（`b<in>aket`）。

| 欄位                              | 預設      | 說明                                                                                    |
| --------------------------------- | --------- | --------------------------------------------------------------------------------------- |
| `cost`                            | 0.3       | 每個構詞步驟的預設成本（個別詞綴、重疊、構詞音變可以用自己的 `cost` 覆寫）              |
| `minStem`                         | 3         | 詞根（詞庫詞）的最短長度（code point），太短的詞根容易巧合命中；見[步數預算](#步數預算) |
| `maxSteps`                        | 3         | 前綴、後綴各自最多幾個（見[步數預算](#步數預算)），整數 0–10                            |
| `lemmaSpread`                     | 0.6       | 詞根相符只保留成本在「最佳 ＋ lemmaSpread」之內的詞幹，控制候選數                       |
| `vowels`                          | `aeiouéə` | 元音字母，決定首輔音、中綴的位置與重疊模板                                              |
| `prefixes`、`suffixes`、`infixes` | —         | 詞綴清單，見[詞綴](#詞綴)                                                               |
| `reduplication`                   | —         | 重疊型式，見[重疊](#重疊)                                                               |
| `circumfixes`                     | —         | 環綴（兩側一起算一個步驟），見[環綴](#環綴)                                             |
| `alternations`                    | —         | 構詞音變（只在詞素交界適用的規則），見[構詞音變](#構詞音變)                             |

**構詞文法寫法**：`prefixes`、`suffixes`、`infixes`、`reduplication`、`circumfixes` 也可以改寫成文法：

- `morphemes`：最小詞素，帶同位詞素與條件；
- `constructions`：組合規則，寫出推導順序與意義；
- `unattestedPenalty`、`conditionPenalty`：兩種懲罰。

見[構詞文法](#構詞文法)與 [morph-grammar.md](morph-grammar.md)。同一份規格只能用一種寫法。

已移除的欄位 `lemmaDistance`、`affixDistance`（音變改以整個詞計算），以及構詞音變的 `before`，出現時 `babizu check` 會報錯並說明原因。

每一筆詞綴、重疊、構詞音變都可以加：

| 欄位    | 說明                                                                       |
| ------- | -------------------------------------------------------------------------- |
| `gloss` | 顯示用的語法說明，字串或依語系的物件 `{ "zh-TW": "主事焦點", "en": "AF" }` |
| `cost`  | 這一步的成本，覆寫預設的 `cost`                                            |
| `ref`   | 出處，例如 `"Li & Tsuchida 2001, p. 15"`。只供維護者查證，不顯示           |
| `note`  | 附註，例如歸類的理由或限制。只供維護者查證，不顯示                         |

拼錯的欄位名稱（例如 `suffix`、`costs`）會被當成錯誤，而不是默默忽略。

演算法（BCDP）的正式定義、推導與正確性證明見 [bcdp.md](bcdp.md)。

## 編寫指南

### 方言規則

規則描述的是「同一個詞在兩個方言或兩套拼寫中，會系統性地怎麼不同」。寫之前先找平行的詞對，例如同一個詞在兩個方言的寫法，看差異是否反覆出現。

| 要描述的現象       | 寫法                            | 例子                                                     |
| ------------------ | ------------------------------- | -------------------------------------------------------- |
| 兩個音位互換       | 雙向規則                        | `["u", "o", 0.1]`：巴宰語 u、噶哈巫語 o                  |
| 一個音脫落         | 一側為空字串                    | `["r", "", 0.1]`：閃音 r 的脫落                          |
| 脫落造成元音變化   | 多字元規則                      | `["ar", "aa", 0.1]`：r 脫落後元音延長                    |
| 只在詞尾發生       | 整組 `"position": "final"`      | `["l", "n", 0.1]`：`bintul` ＝ `bintun`，但詞中的 l 不變 |
| 只在詞首發生       | 整組 `"position": "initial"`    |                                                          |
| 只有一個方向       | 物件列 `"bidirectional": false` | 拼寫系統把某個音寫成兩個字母，但反過來不成立             |
| 不同拼寫系統的寫法 | 另成一組，分類名稱標清楚        | `["dz", "d", 0.1]`                                       |

**權重怎麼定**：

- 方言間**系統性**的對應：0.1
- 常見但不規則的對應、拼寫系統之間的差異：0.2–0.3
- 一般替換 1.5、刪除 1.0、插入 0.8，所以一條規則的權重應該遠低於 1，否則等於沒有規則

網站的篩選面板有三段「模糊程度」：精確、標準、寬鬆，對應的距離門檻見 `src/search/engine.js` 的 `FUZZINESS`（門檻隨查詢長度放寬）。以門檻 0.3–0.5 來說，一個詞能容納三到五條 0.1 的規則。

**詞首、詞尾規則在詞素交界也適用**（[bcdp.md](bcdp.md) 1.3）：

- `babulay` 找得到 `babun`：詞尾的 l → n 在加了後綴 `-ay` 之後仍然存在。
- 元音開頭的詞素接在另一個詞素後面時寫出的喉塞音，是一條詞首規則 `["'", "", 0.1]`：它在詞首與每個詞素交界都適用，所以 `tau'alawan`、`kaxi'eder`、`ali~'ali` 都找得到，普通搜尋也把 `'alaw` 視為接近 `alaw`。
- 如果某個語言的詞尾音變在加後綴時會消失，就不要把它寫成詞尾規則。

**沒有位置限制的規則可以跨越詞素交界**：`["aa", "a", 0.1]` 讓 `takitaw`（ta- ＋ kita ＋ -aw）找得到 `kita`。有位置限制的規則只能碰到交界，不能跨越。

### 構詞文法

平面清單只能把組合寫死成一個詞綴（`minu-`、`mau-`），說明時也就只能顯示成一個前綴。文法寫法描述的是**最小詞素**與它們怎麼組合，所以：

- 說明顯示真正的結構：`minubaket` 是 m<in>u-（mu- 之後插入 <in>），`maudanay` 是 m-・<a>・-ay。
- 理論上允許、但沒有收錄的組合也找得到，只是成本較高。

格式與語意的完整定義見 [morph-grammar.md](morph-grammar.md) 第 2、3 節；這裡是編寫時要注意的事。

**詞素**（`morphemes`）

- 每個詞素一筆：`id`、`type`（`prefix`、`suffix`、`infix`、`reduplication`）、`gloss`，以及一個或多個**同位詞素**（`allomorphs`）。只有一個同位詞素時直接寫 `form`（重疊寫 `pattern`）。
- **寫最小詞素**：<a>、<in>、-an、-ay。不要把 `minu`、`mau` 這類組合寫成前綴——它們由推導產生，列成前綴會與組合規則重複，說明也看不到結構。
- **同位詞素的條件** `when`：往後看（前綴、中綴、重疊，以 `^` 開頭）或往前看（後綴，以 `$` 結尾）的條件，看的是加上這個詞素時的**底層**基底。
  - 前綴、中綴、重疊的條件讀到詞根結尾，不讀後綴；後綴的條件讀到詞根開頭，不讀前綴。
  - 詞根上的中綴、重疊不算在基底裡：mu- ＋ b<in>aket 的條件對 baket 檢查。
  - 語法：`V`、`C`（依 `vowels`）、字母、`[…]`、`[^…]`、單一類別上的 `*`、`+`、`?`，以及最外層的 `|`。例如 m- `^V`、mu- `^C+[ua]`、-un `uC*$`。
  - 不支援巢狀量詞與反向參照（它們會讓比對的時間不可預期），驗證時會報錯。
- **條件不成立不是禁止**，而是加 `conditionPenalty`。資料中常有反例（`muaping` ＝ mu- ＋ aping），禁止會找不到。
  - 條件與資料矛盾時，先不設條件：巴宰語的主事焦點目前就是如此（檢查點 G1）。
- `free: false`：只在組合規則裡出現的詞素，例如只出現在 ta-…-aw 中的 ta-，它不能單獨剝掉。
- `maxUses`：一個推導中最多用幾次（預設 1）。目前只檢查組合規則的 `sequence`；自由串接的詞綴鏈由 `maxSteps` 限制。

**組合規則**（`constructions`）

- `sequence` 依**推導順序**列詞素 id：[AF, PRF] 是先加 AF（mu-）、再插入 <in>，得到 m<in>u-；[PRF, AF] 是先 <in> 再 mu-，得到 mu-b<in>aket。
- 一條組合規則算**一個**步驟，成本是它的 `cost`；它緊貼詞根、最先套用，一個推導至多一條。不佔 `maxSteps`，外面仍可以接 `maxSteps` 個自由的詞綴。
- 支援兩種形狀：
  - 詞根上的中綴或重疊在最前面，之後只接後綴（[PRF, LF] ＝ <in>…-an）；
  - 至少一個前綴，其中至多一個中綴落在前綴上，後綴可以穿插（[AF, PROG, IRR] ＝ m<a>…-ay）。
- **尚未支援**（驗證時報錯）：
  - 只有後綴的組合規則；
  - 詞根上的運算之後再加前綴，例如 sa-RED。這類詞仍可以用兩個自由步驟找到，只是沒有組合規則的說明。
- 同一種組合每個同位詞素的選擇都會展開，展開後超過 20,000 項是規格錯誤（通常是同位詞素太多的詞素出現在太多組合規則裡）。

**懲罰**

- `unattestedPenalty`（預設 0.2）：沒有收錄的**順序敏感**組合。
  - 例子：中綴落在沒有組合規則的前綴上，k<a>i-。
  - 一般的前綴、後綴串接不算。
- `conditionPenalty`（預設 0.3）：每個不成立的同位詞素條件。
- 兩者都是成本，不是禁止：收錄的組合排在前面，是因為便宜，不是嚴格優先。

**怎麼檢查**

- **格式**：`babizu check`，錯誤會指出是哪個詞素或組合規則。
- **推導**：以推導產生器確認組合規則產生預期的表面形式。

  ```js
  import { derive, normalizeGrammar } from 'babizu/fuzzy'
  derive(normalizeGrammar(profile.morphology), 'udan', [{ id: 'AF' }, { id: 'PROG' }, { id: 'IRR' }]).surface // → 'maudanay'
  ```

- **拆解**：到網站搜尋衍生詞，看「自動拆解」與說明中的詞素與組合規則。
- **兩種實作**：站台設定 `search.morphology.methods` 開放 `chart`（類 pika 剖析器）時，可以在設定選單切換，確認兩者的結果相同。
- 有「衍生詞 < 詞根」或詞素層級分析的資料時，量詞根與拆解的正確率。pazeh-kaxabu 以潘德興詞彙表的詞素分析當金標準，工具在私有 repo。

**常見誤區**

- **把組合寫成單一前綴**（`mau-`、`minu-`）：與組合規則重複，說明看不到詞素。改寫成組合規則。
- **條件寫得太嚴、又期待它是禁止**：條件只加懲罰。資料有反例時先不設。
- **以為條件看的是查詢**：條件看的是底層的詞根與詞綴，查詢上的方言音變不影響它。
- **把詞根上的運算之後才加的前綴寫進組合規則**（sa-RED）：目前不支援，驗證時會報錯。

### 詞綴

`form` 寫成**搜尋鍵的形式**：不含連字號，經過同一套正規化（大小寫、`charMap`）。

- **每個異體各寫一筆**。巴宰語的主事焦點前綴有 `m-`、`ma-`、`me-`、`mi-`、`mu-`，依詞根的第一個元音而定；搜尋只需要「剝得掉」，不必知道條件，所以五個都列出來。
- **主事與非主事形式都要列**，例如 `ma-` 與 `pa-`、`maxa-` 與 `paxa-`。
- **詞綴與詞根之間的音變不要列成異體**，寫成規則：插入的喉塞音（`kaxi'eder`、`pu-batu'-an`）是詞首規則 `' → ∅`，交界的元音合併（`maxa-apux` 寫作 `maxapux`）是 `aa → a`。這些規則對整個詞計算，在每個交界都適用。
- **中綴出現在前綴之中**（`m<in>u-baket` 寫作 `minubaket`）：平面清單寫法只能把整段 `minu` 列為前綴（分析器的中綴只插在詞幹的首輔音之後）。文法寫法改寫成組合規則 [AF, PRF]，見[構詞文法](#構詞文法)。
- **方言規則描述得到的差異不必列**：噶哈巫語 `mo-` 對巴宰語 `mu-`（u ↔ o 是 0.1）由規則處理，說明中標為「前綴」上的音變。規則描述不到的（中綴在前綴中）才列成異體。
- **單一字母的詞綴要謹慎**：`a-`、`i-`、`m-` 這類詞綴能剝的地方很多，雜訊（其他詞幹）會明顯增加。只收文法來源確實列出的。

`gloss` 取自文法來源的說明。沒有說明的就不填，介面只顯示形式。

### 重疊

重疊部分放在詞幹前面，由**詞幹**依模板產生。模板以 `vowels` 區分元音與輔音：

| `pattern` | 重疊部分                                    | 例子                            |
| --------- | ------------------------------------------- | ------------------------------- |
| `Ca`      | 首輔音（群）＋ a；元音開頭的詞幹只有 a      | `da~dius`、`la~luzuk`、`a~alep` |
| `CV`      | 首輔音＋第一個元音                          | `ki~kiliw`、`du~dusa`           |
| `CVV`     | 首輔音＋第一個元音，元音加長                | `dee~depex`、`kii~kita`         |
| `CVCV`    | 從頭到第二個元音核為止（兩音節、去韻尾）    | `kipu~kipud-i`、`luba~lubahing` |
| `CVCVC`   | CVCV 再加上其後連續的輔音（兩音節、含韻尾） | `maa-kudung~kudung`             |
| `full`    | 整個詞幹                                    | `saw~saw`                       |

模板的細節：

- **首輔音**是第一個元音之前的所有字元，可以是空的，也可以是輔音群。
- **元音核**是連續的元音字母，`aa`、`iu` 都算一個。所以 `ziux` 只有一個元音核，CVCV 不適用；如果這個語言的元音連續其實分屬兩個音節，目前的模板描述不到（[bcdp.md](bcdp.md) 第 15 節的已知限制）。
- 不在 `vowels` 中的字元都算輔音，包括滑音 `y`、`w` 與喉塞音 `'`：`CVCV` 套在 `zizay` 上得到 `ziza`，韻尾的 y 去掉了。
- **模板只看詞幹，不看後綴**：`kipu~kipud-i` 的重疊部分由 `kipud` 產生。
- **重疊部分複製查詢的形式**：噶哈巫語 `maa-tono~tono` 的重疊部分跟著噶哈巫語的元音，詞幹 `tono` 再以方言規則對應到詞根。
- 同一種重疊語意在不同方言用不同模板時，兩種都列（巴宰語 CVCV、噶哈巫語 CVCVC）。
- 沒有單獨詞根的詞彙性重疊（例如只以重疊形式出現的名詞）不要當成構詞：它們本身就是詞庫中的詞。

### 環綴

`circumfixes` 描述一起出現的兩側詞綴：一個左邊的部分與一個後綴，合起來算**一個**構詞步驟。

```json
{ "prefix": "ta", "suffix": "aw", "gloss": { "zh-TW": "勸說・受事焦點", "en": "HORT.UVP" } }
{ "infix": "in", "suffix": "an" }
{ "reduplication": "Ca", "suffix": "ay" }
```

- 左邊的部分三選一：`prefix`（前綴）、`infix`（中綴）、`reduplication`（重疊型式）。
- **環綴緊貼詞根**：前綴式的左邊是最內層的前綴，後綴是最內層的後綴；其他詞綴只能加在外面：主事焦點前綴可以加在重疊式環綴 `Ca-…-ay` 的外面，但 `ta-…-aw` 的兩側之間不能再夾別的前綴。
- **為什麼需要**：只列前綴 `ta-` 與後綴 `-aw` 時，`ta-kita-aw` 要付兩個步驟的成本，會排在只用一個詞綴、音變較多的錯誤詞根之後。語法描述為一個構式（例如焦點、語氣表中的一格）的，就寫成環綴。
- 環綴的兩側不必另外列在 `prefixes`、`suffixes` 中；列了也沒關係，單獨出現時照樣可以分析。
- 主事焦點前綴有幾個異體時（`m-`、`mu-`、`mi-`、`me-`、`ma-`），每個異體各寫一筆，與詞綴相同。

### 構詞音變

`alternations` 描述**由構詞引起**、只在詞素交界發生的音變：底層的 `underlying` 在交界旁寫成 `surface`。它就是一條只在交界適用的規則（source ＝ `surface`，target ＝ `underlying`），與方言規則在同一個 DP 中計算。

```json
{ "underlying": "t", "surface": "d", "position": "final", "cost": 0.05 }
```

巴宰語詞根末的濁塞音在詞尾清化，只在元音開頭的後綴前出現：`alep` ＋ `-i` → `alebi`，`bitut` ＋ `-un` → `bitudun`。

- `position` 說明 `underlying` 在交界的哪一側：`final`（預設，詞素結尾、交界之前）、`initial`（詞素開頭、交界之後）、`any`（任一側）。
- 交界上的增生也是構詞音變：u 結尾的詞素接元音開頭的後綴時插入 w（`apu'apu-w-an`），寫成 `{ "underlying": "u", "surface": "uw", "position": "final", "cost": 0.1 }`。
- 沒有「只在某些後綴前」的條件：交界就是條件。需要區分時，通常表示那其實是詞綴的異體，列在詞綴清單中。
- **成本要低於對應的方言規則**。方言規則「濁化」t ↔ d 是 0.1 時，把構詞音變設為 0.05：兩種解釋都成立時，說明會顯示為構詞音變，而不是方言差異。
- 構詞音變不佔用步數預算，也不算「至少一個構詞步驟」：它是音變，不是步驟。
- `underlying`、`surface` 可以是多個字元，但參考用的 WFST 後端不支援構詞音變，比較時先去掉。

### 交界語意

- **構詞不跨越空白**：詞綴、中綴、重疊部分都不能含空白，詞素交界也不能在空白旁（`mu daux` 是兩個詞）。片語中每個詞的構詞交給搜尋引擎的逐詞搜尋。
- **詞幹可以含空白**：詞庫中含空白的詞條（複合詞）可以當作詞幹。
- **詞首、詞尾規則在詞素交界也適用**，沒有位置限制的規則可以**跨越**交界（見[方言規則](#方言規則)）。
- **構詞音變只在交界適用**（見[構詞音變](#構詞音變)）。
- 中綴、重疊的交界固定在查詢的位置上，規則不能跨越。

### 步數預算

- 前綴至多 `maxSteps` 個，後綴也至多 `maxSteps` 個，**各自計算**：`maxSteps` 為 3 時，三個前綴加兩個後綴也可以。
- 另外至多一個**非串接步驟**：中綴、重疊或環綴。中綴之後再重疊這類組合目前不支援。
- 每一步都要付成本，所以步數多的分析自然排在後面；`maxSteps` 只是防止列舉爆量，一般不需要改。
- `minStem` 限制的是詞根（詞庫詞）的長度。查詢至少要有 `minStem` ＋ 1 個字元才做構詞搜尋，詞幹在查詢中的寫法可以比 `minStem` 短，只要整個分析的成本在上限內。
- 沒有「詞幹部分的音變上限」：整個分析只受總成本上限與 `lemmaSpread` 限制。

### 怎麼檢查

1. **格式**：`babizu check` 檢查整個設定檔。構詞規格的錯誤會指出欄位，例如 `morphology.reduplication[0].pattern 必須是 Ca、CV、CVV、CVCV、CVCVC、full 之一`。
2. **單一個詞**：到演算法實驗室（`/lab`）輸入兩個詞，逐格檢查編輯距離的計算，確認規則照預期生效。
3. **列舉式分析**：

   ```js
   import { createAnalyzer } from 'babizu/fuzzy'
   const { analyze, generate } = createAnalyzer(profile.morphology)
   analyze('binaket') // → [{ stem: 'baket', steps: [{ type: 'infix', form: 'in', … }], cost: 0.3 }, …]
   generate('baket', [{ type: 'infix', form: 'in' }]) // → 'binaket'
   ```

4. **整體效果**：如果資料中有標註的「衍生詞 < 詞根」，拿它們評估召回、第 1 名的比例與「其他詞幹數」（雜訊）。規格若是從這批詞對學出的，**一定要保留一部分詞對不用來學**，只拿它們評估，否則數字會偏樂觀。pazeh-kaxabu 的做法見其私有 repo 的評估工具與研究紀錄。

### 常見誤區

- **把學出的詞綴全部收進來**。從資料自動學出的清單常有單一字母的「詞綴」與重疊的殘片（例如把 `ta-bura~buray` 的 `tabura` 當成前綴）；它們讓召回多一點，雜訊與耗時卻明顯增加。以文法來源為主。
- **替每個交界現象列詞綴異體**：喉塞音、元音合併寫成規則，一條就涵蓋所有詞綴。只有規則描述不到的（中綴在前綴中）才列異體。
- **構詞音變的成本不低於方言規則**，說明就永遠顯示成方言差異。
- **期待模板看到後綴**，或期待右分支重疊（重疊詞幹的後兩個音節，而不是前兩個）：目前都不支援。
- **把只在詞尾發生、但加後綴就消失的音變寫成詞尾規則**：詞首、詞尾規則在詞素交界也適用。

## 驗證

`babizu check` 會檢查結構（`format`、`version`、型別、構詞規格的每個欄位）；規則內容（權重非負、兩側不同時為空）在建立規則集時檢查。

程式中也可以直接使用：

```js
import { createMetricFromProfile, validateProfile } from 'babizu/fuzzy'

validateProfile(profile) // → 錯誤訊息陣列
const metric = createMetricFromProfile(profile)
metric.distance('ralan', 'lalan') // 0.1
metric.explain('ralan', 'lalan') // 完整 DP 表與對齊路徑
```

搜尋索引的格式與大小不因構詞規格而改變（構詞比對都在查詢時進行）；改了規格只要重新建置網站。精確模式不做構詞比對。
